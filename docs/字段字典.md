# 字段字典 v1

> 依据 `data/schema.sql`。本文件逐表逐字段说明落地字段的类型、必填性、取值与业务含义，不新增结构里没有的字段。字段名一律照抄数据库列名，界面显示名可另定。

## 0 编号与时间约定

**编号规则。** 所有主键都是“前缀 + 定宽十进制序号”，由 `app/db.py` 的 `next_id()` 从 `id_seq` 表分配，不编码章节、难度、年份或地区。序号宽度 6 位，审计日志为 8 位。前缀及用途如下：

| 前缀 | 对象 | 典型值 | 示例 |
|---|---|---|---|
| Q | 题目 | `Q` + 6 位 | `Q000101` |
| QV | 题目版本 | `QV` + 6 位 | `QV000004` |
| SRC | 资料 | `SRC` + 6 位 | `SRC000002` |
| SF | 资料文件 | `SF` + 6 位 | `SF000001` |
| OCC | 出处 | `OCC` + 6 位 | `OCC000007` |
| SOL | 解法 | `SOL` + 6 位 | `SOL000003` |
| TAG | 标签 | `TAG` + 6 位 | `TAG000011` |
| REL | 题目关系 | `REL` + 6 位 | `REL000002` |
| AST | 素材 | `AST` + 6 位 | `AST000001` |
| REV | 审校记录 | `REV` + 6 位 | `REV000021` |
| COL | 题单 | `COL` + 6 位 | `COL000001` |
| SEC | 题单分节 | `SEC` + 6 位 | `SEC000002` |
| ITM | 题单条目 | `ITM` + 6 位 | `ITM000005` |
| RLS | 发布物 | `RLS` + 6 位 | `RLS000001` |
| AUD | 使用对象 | `AUD` + 6 位 | `AUD000001` |
| ASG | 出题任务 | `ASG` + 6 位 | `ASG000001` |
| USG | 使用记录 | `USG` + 6 位 | `USG000001` |
| FB | 教学反馈 | `FB` + 6 位 | `FB000001` |
| INB | 收题箱条目 | `INB` + 6 位 | `INB000003` |
| IMP | 导入批次 | `IMP` + 6 位 | `IMP000001` |
| LOG | 审计记录 | `LOG` + 8 位 | `LOG00000012` |

编号一经分配不再回收，删除记录（仅限过程性对象）也不把序号让给后来者；题目、版本、出处、审校、发布物不物理删除，编号永久指向同一对象。`LOG` 不在首批前缀清单之内，它是 `db.audit()` 的既有实现，列出以便核对。

**时间约定。** 两类时间字段分开写：

| 类别 | 格式 | 生成方式 | 用于 |
|---|---|---|---|
| 时间戳 | ISO 8601 带时区，精确到秒，`2026-10-27T00:30:00+08:00` | `db.now()`，固定 UTC+8 | `created_at`、`updated_at`、`ocr_at`、`at` |
| 日期 | `2026-10-27` | `db.today()` 或人工填写 | `plan_date`、`due_date`、`used_on`、`stat_date` |

时间戳必须带偏移量，便于以后跨时区或多机合并时排序；不存 Unix 秒数，也不存 `2026年10月27日` 一类本地化字符串。界面按本机日期显示，数据库保留原值。`used_on` 是实际使用日期而非登记日期，两者可能相差数日，故单独存日期而不从 `created_at` 推导。

**通用取值约定。** 布尔语义用 `INTEGER` 的 0/1，不用 SQLite 的 `TRUE`/`FALSE` 字面量，便于导出到 CSV 后仍可读。JSON 列存 UTF-8 文本，结构见 `docs/API.md` §12，读取时由 `db.row_to_dict()` 还原为对象。所有外键列在 SQLite 中开启 `PRAGMA foreign_keys = ON`，空值表示“未关联”，不表示“关联到空对象”。

## 1 meta 元信息

单行键值表，记录结构版本与建库时间，供启动时校验与界面显示。不做业务查询。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| key | TEXT | 是（主键） | `schema_version`、`created_at` | 元信息项名 | §14 结构版本与迁移记录 |
| value | TEXT | 是 | 版本号取 `1`；时间取 ISO 8601 时间戳 | 元信息项值 | §14 |

`schema_version` 由 `init_db()` 写入，升级结构时同步改写；`created_at` 只写一次，重复初始化不改写。

## 2 id_seq 编号序列

每个前缀一行，保存下一个可用序号。所有主键由此分配，保证编号连续且不重复。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| prefix | TEXT | 是（主键） | `Q`、`QV`、`SRC`、`SF`、`OCC`、`SOL`、`TAG`、`REL`、`AST`、`REV`、`COL`、`SEC`、`ITM`、`RLS`、`AUD`、`ASG`、`USG`、`FB`、`INB`、`IMP`、`LOG` | 编号前缀 | §14 “ID 使用稳定前缀和编号” |
| next_val | INTEGER | 是 | 大于 0 的整数 | 下一个要分配的值；分配后自增 1 | §14 |

序列只增不减。合并题目、停用标签都不回收编号，被合并对象的编号继续可解析到合并后的对象。

## 3 source 资料

一份可引用的原始资料，如某年期末试卷、某本教材、某份自编练习。资料的“类型”与“使用依据”分栏保存，不互相替代。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `SRC` + 6 位 | 资料编号 | §3 资料 |
| name | TEXT | 是 | 自由文本，如 `2025 学年高一期末` | 资料名称，界面首选显示项 | §3 |
| kind | TEXT | 是 | `exam` 试卷、`textbook` 教材、`workbook` 教辅、`lecture` 讲义、`self` 自编、`other` 其他 | 资料类型 | §3、§8.2 “来源类型单列” |
| edition | TEXT | 否 | 自由文本，如 `2025 学年第一学期`、`第 3 版` | 版次或年份，不同版次分别建资料 | §3 “不同版次分别记录” |
| region | TEXT | 否 | 自由文本，如 `浙江杭州` | 地区 | §3 |
| publisher | TEXT | 否 | 自由文本 | 出版或命题单位 | §3 |
| usage_scope | TEXT | 否 | `校内使用`、`仅个人备课`、`待确认` 等 | 使用范围 | §8.2 “使用范围分栏记录” |
| license_basis | TEXT | 否 | 自由文本，如 `校内自编，不对外发行` | 许可依据，与 `kind` 分开记录 | §8.2 “许可依据与待确认事项分栏” |
| pending_note | TEXT | 否 | 自由文本 | 待确认事项，如授权范围未定 | §8.2 |
| note | TEXT | 否 | 自由文本 | 其他备注 | §3 |
| created_at | TEXT | 是 | 时间戳 | 登记时间 | §5.1 系统生成创建时间 |

`kind` 只是分类，不能当作授权结论：`self` 也要写 `usage_scope`，`exam` 也要写 `license_basis` 或 `pending_note`。

## 4 source_file 资料文件

资料对应的物理文件。同一资料可有多份文件（试卷 PDF、答案页扫描），同一校验值重复上传只提示不重复落盘。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `SF` + 6 位 | 文件编号 | §3 |
| source_id | TEXT | 是 | 引用 `source.id` | 所属资料 | §3 |
| filename | TEXT | 是 | 原始文件名，含扩展名 | 文件名，便于人工辨认 | §4.1 原始证据 |
| rel_path | TEXT | 是 | 相对项目根的 POSIX 路径，如 `sources/SRC000001/期末卷.pdf` | 文件位置，不写绝对路径 | §14 “使用相对位置和校验值” |
| sha256 | TEXT | 否 | 64 位十六进制 | 内容校验值，用于判重与归档核对 | §7.2、§12.3 |
| bytes | INTEGER | 否 | 非负整数 | 字节数 | §12.3 |
| pages | INTEGER | 否 | 正整数 | 页数，供出处页序核对 | §3 |
| uploaded_at | TEXT | 是 | 时间戳 | 上传时间 | §3 |
| note | TEXT | 否 | 自由文本 | 如“扫描件缺第 2 页” | §4.1 |

`rel_path` 指向的文件本身不进数据库，备份时随目录一起复制。

## 5 occurrence 出处

一道题在某份资料中的具体位置。一题可有多条出处，每条可标注它对应哪个题目版本。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `OCC` + 6 位 | 出处编号 | §3 出处 |
| question_id | TEXT | 是 | 引用 `question.id` | 所属题目 | §3 |
| question_version_id | TEXT | 否 | 引用 `question_version.id`；空表示对应当前版本 | 该出处核对的题目版本 | §3 “标明出处对应哪个题目版本” |
| source_id | TEXT | 条件必填 | 引用 `source.id`；自编题可空并在 `note` 写明 | 所属资料 | §5.2 “至少一个来源关联，或自编记录、待确认标记” |
| source_file_id | TEXT | 否 | 引用 `source_file.id` | 具体文件，便于直达页码 | §3 |
| pdf_page | INTEGER | 否 | 正整数，从 1 起 | PDF 页序，用于打开文件后跳转 | §3、§16.2 “均能打开原文件定位” |
| print_page | TEXT | 否 | 自由文本，如 `12`、`12-13`、`卷 2` | 印刷页码，可能与 PDF 页序不同 | §3 |
| qno | TEXT | 否 | 自由文本，如 `8`、`17(2)`、`例 3` | 原题号，保留原资料的编号习惯 | §3 |
| screenshot_asset_id | TEXT | 否 | 引用 `asset.id`（`kind = screenshot`） | 该出处的截图 | §3、§5.1 |
| raw_text | TEXT | 否 | 原文或 OCR 文本 | 识别结果原文，用于比对与查错 | §4.1 识别结果 |
| ocr_tool | TEXT | 否 | 自由文本，如 `手工录入`、`某 OCR 工具 2.3` | 识别工具 | §4.1 |
| ocr_at | TEXT | 否 | 时间戳 | 识别时间 | §4.1 |
| ocr_suspect | TEXT | 否 | 自由文本，指明疑点位置，如 `第 2 行指数位置` | 识别疑点，供人工核对 | §4.1、§13 |
| pending | INTEGER | 是 | `0` 已确认、`1` 待确认，默认 0 | 出处是否待确认 | §5.1、§5.2 |
| note | TEXT | 否 | 自由文本 | 如“原卷此处印刷模糊” | §4.1 |
| created_at | TEXT | 是 | 时间戳 | 登记时间 | §3 |

删除出处的接口受后端限制：题目至少保留一条出处，或把保留下来的那条置 `pending = 1`。删掉最后一条出处会让题目失去可追溯性，属于结构性约束，见末节。

## 6 inbox_item 收题箱条目

尚未整理成题目的原始材料。允许只有文字或文件、来源写“待确认”，不要求答案、标签和难度。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `INB` + 6 位 | 收题编号 | §5.1 |
| raw_text | TEXT | 条件必填 | 原文文本 | 原始文字；与 `file_rel_path` 至少有一项 | §5.1 “人工至少提供原始文字或文件” |
| file_name | TEXT | 否 | 含扩展名的文件名 | 原始文件名 | §5.1 |
| file_rel_path | TEXT | 否 | 相对项目根的 POSIX 路径 | 原始文件位置 | §5.1 |
| source_hint | TEXT | 是 | 自由文本；不清楚时显式写 `待确认` | 来源线索 | §5.1、`API.md` §2 |
| note | TEXT | 否 | 自由文本 | 如“截图不清，第 3 行缺条件” | §5.1 |
| status | TEXT | 是 | `pending` 待提取、`extracted` 已提取待整理、`organized` 已整理、`rejected` 不采用，默认 `pending` | 处理状态 | §5.1、§8.1 整理进度 |
| question_id | TEXT | 否 | 引用 `question.id` | 整理后生成的题目；`organized` 时应填 | §5.1 |
| fail_reason | TEXT | 否 | 自由文本 | 处理失败或不采用的原因 | §9 收题箱“失败原因” |
| operator | TEXT | 否 | 自由文本，如 `教师` | 录入人 | §5.1 |
| created_at | TEXT | 是 | 时间戳 | 登记时间 | §5.1 |
| updated_at | TEXT | 是 | 时间戳 | 最近一次状态变更时间 | §5.1 |

收题条目不是题目：`status` 为 `pending` 或 `extracted` 的条目不出现在可用题检索结果里。同一文件或同一条目重复处理时提示已导入，继续沿用原条目而不新建。

## 7 question 题目

题目的稳定身份与管理信息。数学内容不在这里，而在 `question_version`。难度、推荐等级、预计用时属于管理信息，不进版本。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `Q` + 6 位 | 题目编号，长期不变 | §2 原则 1、§14 |
| short_name | TEXT | 否 | 自由文本，建议不超过 20 字，如 `含参二次方程根的分布` | 简短名称，供列表与题单显示 | §5.2 |
| status | TEXT | 是 | `active` 启用、`inactive` 停用，默认 `active` | 管理状态 | §8.1 |
| status_reason | TEXT | 条件必填 | 自由文本；`inactive` 时必填 | 停用原因，恢复时保留历史 | §8.1 “停用需有原因，可恢复” |
| current_version_id | TEXT | 否 | 引用 `question_version.id` | 当前版本指针，检索与组题默认取它 | §3 题目 |
| merged_into | TEXT | 否 | 引用 `question.id` | 误建重复题合并后指向保留题，查询时跳转 | §7.2 “保留旧 ID 的跳转” |
| difficulty_calc | INTEGER | 否 | 1–5 | 计算难度 | §6.3 |
| difficulty_think | INTEGER | 否 | 1–5 | 思维难度 | §6.3 |
| difficulty_scope | INTEGER | 否 | 1–5 | 综合程度 | §6.3 |
| difficulty_level | TEXT | 否 | 自由文本，如 `高一提高`、`高三一轮` | 难度评价所适用的学生层次 | §6.3 “记录适用学生层次” |
| difficulty_note | TEXT | 否 | 自由文本 | 定级理由，一句话 | §6.3 |
| rec_level | TEXT | 否 | `S` 优先选用、`A` 值得选用、`B` 常规可用、`C` 备用 | 推荐等级 | §6.3 |
| rec_reason | TEXT | 否 | 自由文本 | 推荐理由；与审校结论无关 | §6.3、§8.1 |
| time_solve_min | REAL | 否 | 大于 0 的分钟数，可含 0.5 | 预计独立作答时间 | §6.3 |
| time_explain_min | REAL | 否 | 大于 0 的分钟数 | 预计讲解时间 | §6.3 |
| note | TEXT | 否 | 自由文本 | 个人备注 | §5.2 |
| created_at | TEXT | 是 | 时间戳 | 建题时间 | §5.2 |
| updated_at | TEXT | 是 | 时间戳 | 管理字段最近修改时间；新增版本也算修改 | §5.2 |
| created_by | TEXT | 否 | 自由文本 | 录入人 | §5.2 |

三个难度维度各自独立，系统不合成总分；`rec_level` 不由难度推导，也不由审校结果推导。

## 8 question_version 题目版本

一次提交的完整数学内容。提交后不可覆盖，修改一律新增版本。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `QV` + 6 位 | 版本编号 | §3 题目版本 |
| question_id | TEXT | 是 | 引用 `question.id` | 所属题目 | §3 |
| version_no | INTEGER | 是 | 从 1 起递增，与 `question_id` 联合唯一 | 版本序号 | §3 |
| qtype | TEXT | 是 | `single` 单选、`multi` 多选、`blank` 填空、`solve` 解答 | 题型 | §4.2 |
| stem | TEXT | 是 | LaTeX 文本，公式用 `$…$` | 公共题干，不含选项和答案 | §4.1 规范题面 |
| options | TEXT | 条件必填 | JSON `[{"key":"A","text":"…"}]`；选择题必填 | 选项，`key` 稳定，显示时才排 A/B/C/D | §4.2 |
| answer | TEXT | 条件必填 | LaTeX 文本；多小问按小问分行 | 简明答案 | §4.1 作答内容 |
| answer_keys | TEXT | 条件必填 | JSON `["A"]` 或 `["A","C"]`；选择题必填 | 正确选项标识 | §4.2 |
| subquestions | TEXT | 否 | JSON `[{"key":"1","text":"…","depends_on":[],"answer":"…"}]` | 小问及依赖关系 | §4.2 “保留小问编号及依赖” |
| analysis | TEXT | 否 | LaTeX 文本 | 整题解析；未拆成 `solution` 时使用 | §4.1 |
| material_refs | TEXT | 否 | JSON `["AST000001"]` | 素材引用 | §3 素材 |
| teaching | TEXT | 否 | JSON `{"why","key_step","probe","pitfalls","prereq"}` | 教学说明，不混入题面 | §4.1 教学说明 |
| total_points | REAL | 否 | 大于 0 | 整题分值，可选项 | §4.2 |
| change_note | TEXT | 否 | 自由文本 | 本次修订说明及依据 | §4.3 |
| review_state | TEXT | 是 | `draft` 草稿、`submitted` 已提交，默认 `draft` | 版本提交状态 | §3 “提交后的版本不可覆盖” |
| created_at | TEXT | 是 | 时间戳 | 创建时间 | §3 |
| created_by | TEXT | 否 | 自由文本 | 录入人 | §3 |

`(question_id, version_no)` 唯一是版本不可覆盖的技术底线：想改内容只能插入更大的 `version_no`。`review_state` 只表示提交与否，不代表审校通过；审校结论在 `review` 表中按项记录。

## 9 solution 解法

一条完整的解题路径，挂在具体版本上。一题多解即多条记录，其中至多一条为主解法。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `SOL` + 6 位 | 解法编号 | §3 解法 |
| question_version_id | TEXT | 是 | 引用 `question_version.id` | 所属版本 | §3 |
| label | TEXT | 是 | 自由文本，如 `解法一`、`定义法`、`导数法` | 解法标签，界面显示 | §3 |
| approach | TEXT | 否 | LaTeX 或纯文本 | 思路，即为什么这样想 | §4.1 |
| steps | TEXT | 是 | LaTeX 文本 | 详细步骤 | §4.1 |
| conditions | TEXT | 否 | 自由文本 | 适用条件，如“需 $a>0$” | §6.2 “条件决定方法是否适用” |
| is_primary | INTEGER | 是 | `0`/`1`，默认 0 | 是否教师版选用解法 | §3 “发布时确定选用哪种解法” |
| order_no | INTEGER | 是 | 从 0 起，默认 0 | 显示顺序 | §3 |
| teacher_tip | TEXT | 否 | 自由文本 | 讲评提示 | §4.1 教学说明 |
| created_at | TEXT | 是 | 时间戳 | 创建时间 | §3 |
| updated_at | TEXT | 是 | 时间戳 | 最近修改时间 | §3 |

已发布版本下的解法不允许原地改；要改就在新版本下新增解法。方法标签打在解法上（`solution_tag`），题目层面只汇总展示。

## 10 tag 标签

七个维度的分类字典。标签有稳定编号、定义、别名映射和启停状态，合并时保留旧标签行。

| 字段名 | 类型 | 必填 | 取值 | 含义 | 大纲依据 |
|---|---|---|---|---|---|
| id | TEXT | 是（主键） | `TAG` + 6 位 | 标签编号 | §6.1 |

## 结构性约束

下表列出跨字段、跨表才能成立的约束，以及由谁保证。“数据库约束”指 `schema.sql` 中的主键、外键、`CHECK`、`UNIQUE`；“后端校验”指 `app/api/*` 与 `app/db.py` 的写入前检查；“前端提示”指界面上的阻断或警告，不构成安全边界。

| 约束 | 内容 | 保证方 |
|---|---|---|
| 版本不可覆盖 | `question_version` 以 `(question_id, version_no)` 唯一，修改只能插入新版本；已提交版本不提供原地更新接口 | 数据库约束（`UNIQUE`）+ 后端校验 |
| 版本引用确定 | `collection_item.question_version_id` 非空，题单永远指向确定版本，不跟随“最新版”漂移 | 数据库约束（`NOT NULL`）+ 后端校验 |
| 出处至少一条 | 每道启用题至少一条 `occurrence`，或至少一条 `pending = 1` 的待确认出处；删最后一条时拒绝 | 后端校验 |
| 出处可定位 | 有 `source_id` 时应能给出 `pdf_page` 或 `qno` 或 `print_page` 之一，否则界面警告“无法定位” | 后端校验 + 前端提示 |
| 关系禁自指 | `CHECK (from_id <> to_id)` | 数据库约束 |
| 关系禁成环 | `cond_variant`、`concl_variant`、`param`、`generalize`、`special`、`inverse`、`correction` 写入前做可达性检测，成环则拒绝 | 后端校验 |
| 对称关系成对 | `same_method`、`error_contrast` 同时写反向记录，删除时一并清理 | 后端校验 |
| 审校按项分别记录 | `item` 限定七项，`result` 限定五值；同一对象同一项目可多条，取最新；无记录视为 `pending` | 数据库约束（`CHECK`）+ 后端校验 |
| 审校不因他项通过而豁免 | `stem`、`answer` 不允许 `na`；`figure` 无素材时才可 `na` | 后端校验 + 前端提示 |
| 审校失效传播 | 题面数学内容变化时，题面、答案、相关解析、相关图形重新置 `pending`；只增解法时仅新解法待审 | 后端校验 |
| 可用性判定 | `stem` 与 `answer` 均 `pass`，且至少一条 `solution`（或 `analysis` 视作解析）`pass`；`figure` 为 `fail` 时不可用 | 后端校验（`eligibility`）+ 前端提示 |
| 发布物快照自足 | `release.snapshot` 含题单、条目、题目版本、解法、素材引用与模板版本，重导只读快照 | 后端校验（构建时生成）+ 归档文件 |
| 生成不等于已发放 | `release` 与 `usage_log` 分表；`assignment.status = distributed` 需先有 `release_id` | 后端校验 |
| 不物理删除 | 题目、版本、出处、审校、发布物、使用记录不提供删除；误建题通过 `merged_into` 合并 | 后端校验（无删除接口）+ 数据库外键 |
| 合并可回溯 | 合并时保留旧编号、全部出处、合并记录与历史版本，发布物仍能还原原引用 | 后端校验 + 审计 |
| 停用需理由 | `status = inactive` 时 `status_reason` 必填 | 后端校验 + 前端提示 |
| 标签不物理删除 | 合并写 `merged_into`，停用写 `status`；`(dimension, name)` 唯一防重名 | 数据库约束（`UNIQUE`）+ 后端校验 |
| 维度分离 | 标签 `dimension` 限定七值；方法标签挂解法，不断言在题目上 | 数据库约束（`CHECK`）+ 后端校验 |
| 不产生临时题面 | 题单条目无题面字段；改题面必须新增版本或新建改编题 | 数据库约束（无该列）+ 前端提示 |
| 时间带时区 | 时间戳统一由 `db.now()` 生成，写入前校验含偏移量 | 后端校验 |
| JSON 列结构 | 写入前按 `API.md` §12 校验键名；解析失败时按原文本返回，不抛错 | 后端校验 |
| 正确率需口径 | 记录正确率时必须同时有 `sample_size`、`stat_scope`、`stat_date`、`level` | 后端校验 + 前端提示 |
| 导入可重试 | `import_batch.errors` 逐行记录，部分失败保留成功项 | 后端校验 |
| 写操作留痕 | 所有写接口调用 `db.audit()` | 后端校验 |
| 备份一致 | 备份走 SQLite 在线备份 API，不在写入中复制单个文件 | 后端校验（`db.backup()`） |

其中“出处至少一条”“关系禁成环”“可用性判定”“快照自足”四项无法用 SQLite 的声明式约束表达，必须由后端在写入与构建时检查；前端只做提示，不作为判定依据。

### 26.8 与主表的边界

- 采纳前不产生 `Q/QV/AST` 编号；`source_file` 在采集阶段就登记，原件按 SHA-256 去重。
- 采纳新建版本时写 `question_version.review_state = 'draft'`；`teaching.ai_math_review` 分两条路径：教师手动采纳为 `pending`，AI 自复核自动入库为 `ai_self_review`。
- 自动入库（2026-10-27 政策）会写 `review`：`question_version` 的 stem、answer，每个 `solution` 的 solution，以及每个 `material_refs` 素材的 figure 均记 `pass`；`reviewer` 固定为「AI 自复核（<model> / <prompt_version>）」。`review.reviewer` 是区分人工与 AI 审校的依据，`_eligibility` 会把这类题判为可用。
- 已采纳题目重跑走 `POST /api/ai/questions/{qid}/retry`，revision 递增、旧候选保留。


## 排版扩展

`collection.layout_options`：可空TEXT，保存JSON对象 `{options, items}`。`options`为整卷封面、标题、版面与显示选项；`items`按题单条目编号保存留白、题前分页、同页约束和选项排列覆盖。读取时解析为对象，正式导出写入快照；不改变题目版本。详见[讲义排版预览](讲义排版预览.md)。
