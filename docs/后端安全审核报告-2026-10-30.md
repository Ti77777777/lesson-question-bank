# 后端安全审核报告（2026-10-30）

对象：题库系统后端（v0.9.5 基线，73 个 Python 模块、130 条 HTTP 路由）。
方法：静态审阅 + 用临时数据库起真实服务发恶意请求 + 真实 XeLaTeX 沙箱试验。未改业务代码。
威胁模型：本机单用户、只监听 127.0.0.1；需要防的是**浏览器里的其他网站**借用户浏览器打本机接口，以及**恶意文件**（PDF、备份 ZIP、TeX、AI 输出）进入处理链路。

## 1. 结论

**没有发现可被远程直接利用的注入、越权或任意文件读写。** 关键防护（Host/Origin 校验、路径白名单、参数化 SQL、TeX 沙箱、密钥隔离）在实测中都成立。
发现 9 项问题，均为**本机攻击面或纵深防御**级别：其中 3 项建议处理（无认证、备份可带代码、模型地址可指向内网），其余为低危或协议/资源问题。

## 2. 发现

### S1（中）没有认证，任何本机进程或同机用户都能读写全部数据

- 位置：`app/server.py` 全部路由；无 token、无会话、无登录接口。
- 证据：只校验 Host 白名单与写入请求的 Origin；用普通 HTTP 客户端（非浏览器）可调用全部接口，读写题目、学生名单、使用反馈与备份。
- 影响：单用户独占的机器上可接受；但学校共用电脑、或机器上已有恶意进程时，隐私数据（学生姓名、考试卷）与内容完整性都没有保护。
- 建议：如仍需单机形态，至少提供可选的"本机令牌"（启动时生成，页面 URL 带上，写入/读取都要求），或在 README 明确"仅建议个人专用电脑使用"。

### S2（中）完整备份包含可执行代码，恢复后启动即执行备份里的程序

- 位置：`app/full_backup.py:17`（`DIRECTORIES` 含 `app`）、`:48`（白名单放行）、`:151-153`（生成 `恢复启动.bat`，内容是 `python run.py`）。
- 证据：备份 ZIP 打包 `app/`、`run.py`；恢复时原样写出并生成启动脚本，双击即运行压缩包里的代码。
- 影响：导入本身不执行，但"收到一份他人备份 → 导入 → 恢复 → 双击启动"就会执行对方的 Python 代码，属社会工程型供应链风险。
- 建议：备份只收数据与素材（`sources/assets/releases/data`），`app` 由恢复时从当前安装复制；或恢复前校验 `app/` 与当前版本哈希一致。

### S3（中低）模型接口地址允许任意 HTTPS，包括内网与链路本地地址

- 位置：`app/ai/settings.py:37-46`。
- 证据：`POST /api/ai/settings` 接受 `https://169.254.169.254/latest`（实测 200）；HTTP 仅允许 localhost。DPAPI 密钥按 `base_url` 哈希分文件（`credentials.py:11-19`），换地址不会复用旧密钥——这点正确。
- 影响：本机用户（或被诱导恢复他人数据库后）可让服务向任意 HTTPS 主机发请求；配合 `key_env`（环境变量式密钥）会把对应环境变量发给该主机。
- 建议：默认拒绝私网/链路本地/回环的 HTTPS 地址，或保存时二次确认；文档写明"不要导入来路不明的完整备份"。

### S4（低）GET 接口会持有数据库写锁

- 位置：`app/api/layout.py:73-79`，`GET /api/collections/{cid}/layout` 用了 `db.transaction()`（`BEGIN IMMEDIATE`）。
- 证据：另开连接持写锁时，该 GET 3 秒无响应；同一时刻 `GET /api/meta` 立即返回（WAL 读不互斥）。工程里已有 `db.read_transaction()` 未被使用。
- 影响：GET 不做 Origin 校验，其他网站可用 `<img>` 触发；放大写锁竞争，页面自动保存可能遇到 `database is locked`。
- 建议：改用 `read_transaction()`。

### S5（低）两个 GET 接口有副作用

- 位置：`app/api/ai.py:205-224`，`GET /api/ai/jobs/{jid}/pages` 与 `/pages/{page}` 调用 `documents.prepare()`——渲染 PDF 页面、写 manifest 缓存并 `UPDATE source_file.pages`。
- 影响：每次首次访问代价较高（PDF 渲染），GET 可被跨站触发（需知道 AIJ 编号），属资源消耗面。
- 建议：改为 POST，或明确它是"缓存预热"并在响应里标注。

### S6（低）HEAD / OPTIONS 未实现

- 证据：`HEAD /api/meta` 返回 `501 Unsupported method`；而 `app/server.py:226` 已按 HEAD 不发送 body，说明本意是支持的。
- 影响：监控、反向代理、部分客户端探测会误判服务不可用；不是安全漏洞。
- 建议：加 `do_HEAD = _dispatch`；OPTIONS 返回 `Allow` 或不实现都可。

### S7（低）资源耗尽面

- 备份导入把最大 512MB 请求体整体读入内存（`server.py:170-175`）；ZIP 校验限制解压后 4GiB，但不查压缩比；`?limit=-1` 在 SQLite 等价于"不限量"（多个列表接口未夹紧范围）。
- 影响：本机可触发内存/磁盘压力或一次拉全表；单用户场景风险低。
- 建议：limit 夹到 1–500；导入改流式落盘；ZIP 增加压缩比上限。

### S8（低）本机信息暴露

- `GET /api/meta` 返回项目绝对路径与库文件路径；`/api/audit` 可读全部操作日志（含姓名与修订说明）。仅本机可访问，属低危。

### S9（低）CSP 缺少脚本来源限制

- 证据：页面响应 CSP 只有 `frame-ancestors 'self'`。
- 影响：当前前端模板抽查均做了 `esc`/`badge` 转义，暂无可利用的存储型 XSS；但一旦出现，CSP 无法兜底。
- 建议：加 `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`（注意 KaTeX 走 CDN，需要一并放行或本地化）。

## 3. 已验证成立的防护（留档）

- Host 严格白名单：伪造 Host、后缀、重复 Host、尾点 Host 均 403；DNS rebinding 不可行。
- 跨站写入：Origin 不符、`Sec-Fetch-Site: cross-site` 均 403；无 CORS 允许头；`Cross-Origin-Resource-Policy: same-origin`。
- 路径：`/files` 与静态目录的 `..`、编码穿越、绝对路径、敏感目录（数据库、凭据、源码、备份）全部 404；符号链接经 `resolve()` 后同样越界。
- 上传：按魔数校验扩展名，HTML/SVG/伪装文件被拒；"PNG 魔数 + HTML" 上传后以 `image/png` + `nosniff` 返回，浏览器不会当页面执行。
- 备份 ZIP：`..`、绝对路径、符号链接、清单不一致、超限均拒绝；下载 ID 有格式白名单。
- SQL：全部占位符参数；动态表名/列名来自白名单；排序只走固定分支。
- AI 输出契约：命令白名单、`\input`/`\write18` 等拒绝、题图路径限 `assets/`、`$` 配对、公式嵌套与中文标点检查。
- LaTeX 编译：`-no-shell-escape`、`openin_any=p`、`openout_any=p`、子进程剔除 `*_API_KEY`/`*_TOKEN`。实测：`\input{C:/Windows/win.ini}`、`\input{../secret.txt}` 均失败；`\write18{...}` 未执行；`\input|"cmd ..."` 失败。
- 密钥：DPAPI 按 Windows 用户加密、按 `base_url` 哈希隔离；`/files` 无法下载；完整备份不含 `data/private`；接口不回显密钥。
- 元信息转义：标题/页眉/来源标签在进 TeX 前走 `plain()` 转义（覆盖 `\{}$&#_^~`），题干与解析按设计保留原始 TeX。

## 4. 未覆盖

- 真实浏览器组合攻击（多个 localhost 端口、代理、iframe sandbox）未做端到端验证。
- 三方库漏洞（pdfplumber / pypdfium2 / Pillow）未做版本比对与恶意样本测试。
- 未做模糊测试；AI 提示注入只验证了输出契约与编译面，未做端到端对抗样本。
- 未审计前端全部 40 个模块，只抽查了题目、检索、题单、名册相关模板与 `badge`。

## 5. 建议顺序

1. S1 认证/威胁模型（决定这个项目能否放到共用电脑）。
2. S2 备份不带可执行代码（防社会工程）。
3. S3 限制私网地址（防 SSRF/密钥外发）。
4. S4、S5、S6 小修（写锁、GET 副作用、HEAD）。
5. S7–S9 按需加固。
