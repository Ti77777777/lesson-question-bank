# 代码审核报告（2026-10-30）

审核范围：整个 `题库系统`（应用 v0.7.0，共 130 条 HTTP 路由、40 个前端模块、24 个 Python 测试模块 + 7 个前端测试）。
方法：读源码 + 跑测试 + 路由/调用对账 + 静态扫描 + 隐私扫描；不修改业务代码。

## 1. 结论

主体质量高：路由与前端调用完全对得上，没有 SQL 注入、路径穿越、命令执行或未转义的用户文本；写操作普遍有事务、修订号、幂等编号与审计。发现 **9 个问题**，其中 3 个建议优先处理。

## 2. 发现的问题

### P1-1 测试库备份混入正式备份目录

- 位置：`app/db.py:193-203` `backup()`。
- 现象：`target_dir` 默认 `ROOT/"backup"`，文件名固定 `qbank-<时间戳>.db`，没有按库分目录，也没有带库标识。
- 证据：本次审核运行 `tests/test_flow.py` 时生成了 `backup/qbank-20261030-001225.db`，其 `question` 表只有 5 题、题单是「函数的单调性」——确认是测试临时库；它与正式库备份同名同构，并排在 `backup/` 下（该文件已在审核后删除以免混淆）。`backup/_test_features/full`、`backup/_direct_layout_*/full` 同样是测试留下的目录。
- 风险：手工恢复时可能把测试库当成正式备份覆盖回去。
- 建议：改用 `db.store_dir('backup')`，文件名带库标识（`<stem>-<时间戳>.db`）；测试清理临时目录。项目检查报告 P2 早已提出同一问题，尚未落实。

### P1-2 干净仓库里 `tests/test_flow.py` 必然失败

- 位置：`tests/test_flow.py:313-314`。
- 现象：断言发布物归档含 `ExBook.cls` 与 `img/cover.jpg`。
- 证据：`git ls-files templates/exbook` 只有 `ExBook.cls`、`LICENSE`；`templates/exbook/img/` 从未入库，README 末段也写明「封面插画及推广水印均不在源码包中」；`app/latex/build.py:347-352` 已把封面/水印图当作可选。本次运行结果：`合计 42 项，通过 41 项`，唯一失败就是这一条。
- 影响：新机器克隆后跑真实编译测试必然红，容易被当成功能回归。
- 建议：断言改为「归档含 `ExBook.cls`」；若要保留图片检查，把它标成需要本地素材的可选检查。

### P1-3 自动入库遇到单题异常会中断整批

- 位置：`app/ai/adopt.py:200-212`。
- 现象：逐题 `accept_candidate` 只捕获 `ApiError` 与 `ProviderError`；若候选内容异常（`KeyError`、`TypeError` 等）循环直接中断，后面的合格题不再入库。
- 放大：异常继续向上抛，`worker._loop` 的 `except Exception: pass` 会吞掉；此时 job 已被标成 completed/partial，界面上看不出有题没入库。
- 建议：单题 `except Exception`，写 `ai_auto_adopt_failed` 审计（带异常类型）后继续下一题。

### P2-1 逐题反馈并发提交返回 500

- 位置：`app/api/teaching.py:2077-2095`。
- 现象：`existing = db.one(SELECT ... usage_item_feedback ...)` 在 `with db.transaction()` **之前**执行；两个并发提交（双击、断线重试）都可能读到「没有」，第二个 INSERT 撞 `ux_uif_usage_item` 唯一索引，`IntegrityError` 未捕获 → 500。
- 与设计不符：0.7.0 记录的是「同一使用记录里的同一题重复提交是更新而不是新建」。
- 建议：把查询移进事务；捕获 `IntegrityError` 后退回更新。

### P2-2 API 文档落后于实现

- 位置：`docs/API.md`。
- 缺失：`POST /api/items/{iid}/swap`、`GET/POST /api/usages/{uid}/item-feedback`、`GET /api/collections/{cid}/version-updates`（及 apply）、`/api/backups`（创建/导入/下载/检查/恢复）、`/api/search/presets`（增删改查）、`/api/source-changes`（含撤销）、`GET/POST/PATCH /api/questions/{qid}/corrections`。
- 建议：补齐或在文首注明「AI、备份、纠错、检索方案见各自说明文档」。

### P2-3 五个提交未推送

- 证据：`git status --porcelain` 为空，`git branch -vv` 显示 `main ... [origin/main: ahead 5]`（0.5.1–0.7.0 五个发布提交）。
- 影响：违反 `AGENTS.md` 的「每轮推送并核对远端」；本机故障会丢 5 轮工作。
- 建议：网络可用时 `git push origin main` 并核对远端提交。

### P3-1 两个测试文件不能按脚本直跑

- `tests/test_text_preview.py`、`tests/test_public_package.py` 缺 `sys.path` 引导，`python tests/xxx.py` 报 `ModuleNotFoundError: app / scripts`。
- 官方 `scripts/test_backend.py` 用 `-m unittest discover`（cwd=根目录）不受影响，两个模块在其中能过（加 `PYTHONPATH` 复跑验证过）。与其他测试「可直接运行」的惯例不一致。

### P3-2 封面/水印常量与配置残留

- `app/latex/exbook.py:16-17` 仍定义 `COVER_FILE/WATER_FILE`，`:543-544` 仍输出 `\CoverImg{img/cover.jpg}`、`\WaterImg{img/water.png}`；仓库不含 `img/`。
- v1.2 极简封面不排这两项，因此当前不报错，但属于死配置；`docs/模板接口.md:97,111` 仍写默认 `img/cov01.jpg`，与现状不一致。

### P3-3 删除检索方案不校验存在

- `app/api/workspace.py:58-63`：删除不存在的方案也返回 `{"ok":true}`，前端无法区分「已删除」与「本来就不存在」。

## 4. 未覆盖

- 浏览器交互（折叠、拖拽、自动保存、撤销按钮）未人工点验，仅测了纯函数与模块加载。
- 未调用真实模型（不产生费用）；多协议适配只用本地假响应验证。
- 扫描件、双栏、手写样卷仍未测（原设计阶段 F）。

## 5. 建议处理顺序

1. P1-1 备份分库 + 清理测试残留（有误恢复风险）。
2. P1-2 修正 test_flow 断言（让回归信号可信）。
3. P1-3 自动入库逐题容错（直接影响 AI 入库结果）。
4. P2-1 逐题反馈并发、P2-3 推送、P2-2 文档补齐。
5. P3 按需清理。
