# 标签规范 v1

> 依据 `data/schema.sql` 的 `tag`、`question_tag`、`solution_tag`。本文件规定七个维度的判断边界、命名规则、首批标签、以及合并与停用办法。标签是检索与组题的依据，不是题目的装饰。

## 1 七个维度

标签的维度先于名称。同一个词在不同维度上是不同标签，例如“单调性”作为知识点存在，作为前置知识也存在，二者不可互换。使用前先问“我在按什么筛题”，再决定维度。

### 1.1 knowledge 知识点

指这道题考的是什么数学内容，按教材的概念体系归位。

**包含**：集合与逻辑、函数性质、指数与对数、三角函数、数列、不等式、导数、立体几何、解析几何、概率统计中的概念与结论。

**不包含**：解题动作（那是 method）；某道题的具体条件（如“含参二次方程”不是知识点，`二次函数` 才是）；教材册次章节（那是 textbook）；学生是否学过（那是 prereq）。

**判定问句**：如果一个学生完全掌握了这一条，他是否就具备了做对这道题所需的主要数学知识？答“是”才选。

每道正式整理题原则上有一个主考点 `primary`；确有两个并列目标时可设置两个。辅助考点 `secondary` 按实际需要填写，避免把仅偶然出现的概念全部打标。主考点取最能解释训练目标的知识，不机械采用最后一步用到的知识。

### 1.2 textbook 教材位置

指这道题对应教材的哪一册、哪一章、哪一节，用于按教学进度取题。

**包含**：教材版本、册别、章、节，按“版本 · 册别 · 章 · 节”分层，父标签为上一层。

**不包含**：知识点本身（同一知识点可能跨章节）；考试范围（那是题单的 `coverage`）；难度。

**判定问句**：这一节讲完后，在所选解法的前置知识范围内，这道题能否作为配套练习？跨节综合题可关联多个实际对应的教材位置，注明主要位置；不把教材进度与知识点归属混为一项。

教材位置不强制与知识点一一对应：一个知识点可以落在多节，一节也可以覆盖多个知识点。

### 1.3 prereq 前置知识

指做这道题之前必须已经会的东西，用于判断学生是否具备基础、以及讲解时要补什么。

**包含**：更早学过的概念、变形技能、运算律、图形读法。

**不包含**：本题正在训练的目标（那是 knowledge）；解题策略（那是 method）。前置知识与所考知识必须分开，否则无法回答“学生卡在哪”。

**判定问句**：如果学生在这一条上出错，是否说明他缺的是旧知识而不是本题方法？答“是”才选。

每题 0–3 个。前置知识填得越多不等于越严谨，只填真正会卡住学生的。题单的 `prereqs` 字段应能由所含题目的前置知识汇总得到。

### 1.4 method 解题方法

指解这道题所用的可操作手法，标在**具体解法**上，不标在题目上。

**包含**：可以写成步骤的办法，如定义法、配方法、换元法、判别式法、参数分离法、导数法。

**不包含**：数学思想（那是 idea）；知识点名称；某道题特有的技巧（若只对一题有效，写进解法的 `approach` 或 `teacher_tip`，不建标签）。

**判定问句**：换一道同类的题，这个方法还能照用吗？答“能”才建标签。只能用于一题的做法写进解法文本。

一题多解时，每个解法各打各的方法标签；题目层面的“方法”由解法汇总而来，不单独录入。这样“按方法筛题并排除超出学生基础的解法”才有依据。

### 1.5 idea 数学思想

指解题背后的总体观念，与具体操作分栏。

**包含**：数形结合、分类讨论、转化与化归、函数与方程一类统摄性观念。

**不包含**：具体步骤（那是 method）；教学安排（那是 purpose）。思想标签允许一题多个，也允许与任何方法标签并存，二者不互斥。

**判定问句**：这条描述的是“为什么这样想”，而不是“怎么做”？答“是”才选。

思想标签一律四字，便于在题单的覆盖统计中并列显示。

### 1.6 purpose 教学用途

指这道题适合在课堂上承担什么任务，是题目的**建议**，不是安排。

**包含**：诊断、例题、变式、巩固、易错辨析、方法示范、概念引入、课后作业等。

**不包含**：某份题单里的实际角色（那是 `collection_item.role`）；推荐等级（那是 `question.rec_level`）；启用状态。同一道题在两份题单里可以是例题，也可以是跟练，`purpose` 只记录它更适合哪一种。

**判定问句**：这道题最不可替代的用处是什么？只写一个主用途，其他写辅助。

一题 0–2 个 purpose。基础口算题可以不填。

### 1.7 error 错误类型

指学生在这道题上容易出现的具体错误，用于错因追练与讲评提示。

**包含**：可观察的错误现象及其后果，如忽略定义域、遗漏等号、必要条件当充分条件。

**不包含**：知识缺口（那是 prereq）；难度评价；笼统的“粗心”“基础差”。

**判定问句**：能否在学生的答卷上指出具体哪一行错了？答“能”才选。指不出具体位置的，不建标签。

要区分**预计易错点**与**实际课堂观察**：前者打在题目上，来自教师预判；后者写进 `feedback.common_errors`，来自这一次的作业或测验。两者不互相覆盖。

## 2 命名规则

| 维度 | 词形 | 必须 | 禁止 | 正例 | 反例 |
|---|---|---|---|---|---|
| knowledge | 名词短语 | 用教材术语，可带限定语 | 不加“的”，不写题号，不写难度，不写“专题” | 单调性、一元二次不等式、导数与单调性 | 函数的单调性的判断、第 8 题考点、单调性（难） |
| textbook | 教材全称 + 层级 | 版本、册别、章、节逐级写全 | 不缩写版本名，不写“必修一”这类口语 | 人教A版 · 必修第一册 · 第三章 · 3.2 函数的基本性质 | 必修一函数、人教3.2 |
| prereq | 名词短语 | 写“已经会的东西” | 不写“复习”“巩固”一类动作 | 判别式、韦达定理、区间表示 | 复习判别式、学过二次函数 |
| method | 名词短语，以“法”结尾 | 统一以“法”收尾 | 不写“利用……求解”“用导数做” | 判别式法、配方法、换元法、参数分离法 | 用判别式、导数做、分离参数 |
| idea | 通行的思想名称 | 采用清晰、稳定的名称 | 不写成含糊句子，不为凑字数改术语 | 数形结合、分类讨论、转化与化归 | 数形结合思想方法、分类的思想 |
| purpose | 名词短语 | 写课堂任务名 | 不写“好用”“经典”“必做” | 诊断、例题、变式、易错辨析 | 好题、重点题、必刷 |
| error | 现象 + 后果，或“甲当乙” | 能被指认到具体步骤 | 不写“粗心”“不认真”“基础薄弱” | 忽略定义域、遗漏等号、必要条件当充分条件 | 粗心、算错、没学懂 |

补充四条：

1. 标签名称保持简洁，复杂解释写入 `definition`；不设统一字数上限。教材位置可以使用完整层级名称，不能为了缩短名称丢失版次和章节信息。
2. 同维度内不得重名（数据库 `UNIQUE (dimension, name)`）。跨维度同名允许，但要在定义里写清区别，例如 knowledge 的“单调性”与 prereq 的“单调性定义”。
3. 不在名称里写学生层次、年份、地区。这些是题单与资料的属性，不是标签的属性。
4. 方法标签必须能被另一个教师照着做出来。写不成步骤的，不建标签。

### 3.8 与母题链的对应

以如下三道题为例（`x^2-2ax+1=0` 的两个不相等实根、两个不相等正实根、两个正实根）用上述标签可以完整描述：主知识点取 `二次函数`，辅助知识点取 `单调性`；前置知识取 `判别式` 与 `韦达定理`；解法分别挂 `判别式法` 与 `对称轴法`；思想取 `数形结合`（把实根个数看成交点个数）与 `分类讨论`（按根的位置分情形）；错误类型取 `遗漏等号`（边界变式沿用严格不等式）与 `忽视二次项系数为零`（退化情形）；教学用途依次取 `例题`、`变式`、`巩固`。

“函数单调性”专题所需的标签同样在这一批之内：知识点 `单调性`、`奇偶性`、`二次函数`；方法 `定义法`、`对称轴法`、`导数法`、`参数分离法`；思想 `数形结合`、`分类讨论`；错误 `忽略定义域`、`遗漏等号`。专题题单不必另建标签，只需在组题时按这些标签筛选。

## 4 使用规则

| 规则 | 内容 |
|---|---|
| 主次 | 每题知识点 1 个 `primary`、至多 2 个 `secondary`；`secondary` 不参与“必须包含”筛选的主判定 |
| 位置 | 方法标签只挂 `solution`；题目详情页显示的“方法”由解法汇总，不单独录入 |
| 并存 | `idea` 与 `method` 可同时存在，互不替代；一个解法可以既是判别式法又是分类讨论 |
| 建议性 | `purpose` 是建议。题单里的实际角色写在 `collection_item.role`，两者不一致时不报错 |
| 分离 | `error` 分预计与实际：题目上的为预计，`feedback.common_errors` 中的为实际观察 |
| 数量 | 单题标签总数超过 12 个时，界面提示“标签过密”，建议回到主考点重选 |
| 来源 | 人工打标记 `source = manual`，AI 建议记 `ai`；`ai` 标签须经人工确认后才参与正式筛选 |

## 5 合并与停用

### 5.1 什么时候合并

同时满足两条才合并：两名指同一概念；两者在判断边界上无法给出可操作的区分。仅“意思接近”不构成合并理由。

| 情形 | 处理 |
|---|---|
| 同一概念的不同写法，如“增减性”与“单调性” | 合并，保留使用较多者，另一条写 `merged_into` |
| 上下位关系，如“函数性质”与“单调性” | 不合并，用 `parent_id` 建层级 |
| 一个标签实际混了两个概念 | 拆分：新建两条，旧标签停用并注明拆分去向 |
| 跨维度同义，如 knowledge 的“单调性”与 prereq 的“单调性定义” | 不合并，维度不同，用途不同 |
| 只对某一题有效的说法 | 不建标签，写进解法的 `approach` 或 `teacher_tip` |

### 5.2 合并怎么做

1. 先改 `definition`，把边界写清；边界写不清的，说明不该合并。
2. 调用 `POST /api/tags/{tid}/merge`，`{"into": "TAG000002"}`。
3. 被合并标签置 `status = inactive` 并写 `merged_into`；`question_tag`、`solution_tag` 的关联转到保留标签，原关联保留在历史里供回查。
4. 保留标签的 `definition` 追加一行“原“旧名”并入”，`note` 记录合并时间与理由。
5. 合并可撤销：清空 `merged_into` 并恢复 `status`，关联按合并记录还原。

**禁止物理删除。** 旧标签行必须留着，否则历史筛选、旧题单的覆盖统计与已归档发布物的回查都会断链。

### 5.3 什么时候停用

| 情形 | 处理 |
|---|---|
| 教材换版，旧章节标签不再使用 | 停用，`note` 写“2026 学年起改用新教材”，不合并到新章节 |
| 一批标签定义写得过宽，暂不用于新题 | 停用，`note` 写原因；已有题目的关联保留 |
| 与另一标签重复但尚在核对 | 先停用，核对完再合并；不要先合并再改主意 |
| 临时想到的说法 | 不建标签，写备注并放入待整理清单 |

停用不影响既有题目的检索结果展示，只在新打标时不再出现在候选列表。

### 5.4 禁止临时造近义词

收题、整理、讲评过程中需要的临时说法，写进 `question_version.teaching` 或 `collection_item.note`，不进 `tag` 表。每新增一个标签要回答三个问题：它对应的概念是什么、与已有哪个标签的边界在哪里、至少三道题会用吗。三问答不全的，先不建。

每月集中处理一次待整理清单：合并重复、补定义、停用长期零引用的标签。标签数量增长快于题目数量，说明命名规则没有执行。
