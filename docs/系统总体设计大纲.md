# 习题课题库系统总体设计大纲

文档版本：1.0

更新日期：2026-10-29

实现基线：应用 v0.4.4，提交 `e64a9b3`

文档性质：基于现有实现整理的设计基线与后续实施大纲。本次只更新文档，不改变应用行为。

## 1 定位与设计目标

面向高中数学教师的本地备课系统，围绕一条完整工作流程组织功能：

**收集资料 → 整理题目 → 检查质量 → 检索选题 → 编排讲义 → 导出归档 → 记录使用与反馈。**

系统应帮助教师回答四个问题：这道题从哪里来、是否适合这批学生、如何放进这节课、过去用过之后效果如何。衡量功能价值时，优先考虑能否减少重复录入、降低数学与排版错误、缩短找题和组题时间。

### 1.1 当前范围

- 单教师、本机运行；浏览器操作，资料与数据库保存在本地。
- 服务监听本机地址；普通题库功能使用 Python 标准库和 SQLite，网页使用原生 JavaScript 模块。
- AI为可选能力，PDF与图片处理、讲义编译分别具有独立依赖；未配置时仍可录题、检索和组题。
- 支持学生版、答案版、教师版讲义，共用一份题单及排版设置。
- 面向教师备课与教学记录；本阶段不包含学生在线答题、自动批改、多人实时协作或云端题库交易。

### 1.2 设计原则

1. **数学内容可核对。** 原始证据、规范题面、答案解法、教学说明分开保存；不把AI建议直接表述为教师确认。
2. **题目身份稳定。** 修订内容形成版本，出处和使用记录可追溯；同题多出处与变式题分别处理。
3. **教学安排独立。** 某份讲义的题目角色、留白、选用解法和分页，不反向改写公共题目。
4. **历史输出可解释。** 归档保存当时题目版本、素材、模板与设置，重建不读取当前最新题面。
5. **操作可恢复。** 编辑有草稿，冲突不覆盖，耗时任务有状态，失败保留已完成工作。
6. **功能按需呈现。** 常用操作直接可见，低频设置展开查看；用户界面使用教师熟悉的名称。

## 2 现状与规划的阅读约定

本文使用三类标记：**已有**表示基线源码具备该能力；**待完善**表示已有实现但规则或体验需要统一；**规划**表示尚需设计接口、迁移数据或开发页面。源码阅读不能替代运行验收，本文不声明所有功能已在本轮重新测试。

本文统筹产品范围、模块边界与规则。现有字段以[字段字典](字段字典.md)及SQL结构为依据，已实现接口以[API说明](API.md)及代码为依据；规划字段与接口在实现前不得写成可用能力。后续修改规则时，应在同一轮更新实现、相关文档、验收用例和[更新记录](../CHANGELOG.md)。

## 3 用户任务与页面组织

| 教师任务 | 主要入口 | 完成结果 | 当前状态 |
|---|---|---|---|
| 临时保存题目或材料 | 收题箱、手工录题 | 可继续整理的记录或题目草稿 | 已有 |
| 批量处理试卷 | AI工作台 | 带原卷证据、解答和建议的候选或入库版本 | 已有 |
| 维护试卷信息与出处 | 试卷信息管理、题目详情 | 年份、年级、来源位置可检索 | 已有 |
| 找到适合课堂的题 | 题库检索、详情侧栏、选题篮 | 候选题目集合 | 已有 |
| 组织一节习题课 | 题单与分节 | 题目顺序、教学角色、课时与覆盖要求 | 已有 |
| 制作可打印讲义 | 排版与预览、导出与归档 | 三版文件与固定快照 | 已有 |
| 记录布置与实际使用 | 使用与反馈 | 练习安排、使用题目、课堂观察 | 已有 |
| 从课堂问题生成下一次练习 | 使用与反馈 → 检索 → 新题单 | 有依据的追练题单 | 规划联动；现可手动完成 |

后续入口按任务组织：资料进入收题箱或AI工作台，题目维护从检索和详情进入，讲义制作从题单进入，历史讲义和备份从归档进入。系统设置应统一容纳模型连接、预算默认值、模板与备份入口，现有分散入口可逐步归并；不额外增加只展示统计数字的首页。

## 4 总体架构与模块边界

继续采用模块化单体：一个本地服务管理业务，一个SQLite数据库保存结构化数据，原卷、素材和输出文件保存到受控目录。AI处理在后台执行，TeX通过子进程编译。现有架构可服务当前场景，新增业务优先在内部明确职责。

| 层次 | 职责与现有位置 | 后续边界 |
|---|---|---|
| 页面与交互 | `app/static/pages/`、`app/static/lib/` | 呈现、输入、草稿和操作反馈；质量与发布资格由服务端判断 |
| 接口 | `app/server.py`、`app/api/` | 参数校验、请求响应、错误转换；逐步减少直接承载完整业务流程 |
| 业务规则 | 目前分布于内容、教学、AI采纳、排版等模块 | 提取可复用的题目版本、质量判断、题单检查与发布规则 |
| 数据与文件 | `app/db.py`、两份SQL结构、来源与素材目录 | 事务、稳定编号、相对路径、摘要、审计及数据库升级 |
| 外部能力 | `app/ai/`、`app/latex/` | 隔离协议、费用、超时、文件处理与编译环境；返回明确结果 |

### 4.1 六个业务模块

| 模块 | 自主管理的对象 | 对其他模块提供的能力 |
|---|---|---|
| 资料与来源 | 资料、资料文件、出处、原始证据 | 按页和题号定位、校验文件、来源筛选与显示 |
| 题目与质量 | 题目、版本、解法、标签、关系、审校、纠错 | 查询内容、建立版本、判断质量、解释不能选用的原因 |
| AI处理 | 批次、任务、步骤、证据区域、候选、采纳决定 | 生成候选与建议；通过统一题目业务入口入库 |
| 检索与组题 | 常用检索、题单、分节、题单条目 | 筛选选题、锁定版本及解法、检查教学安排 |
| 排版与归档 | 排版设置、样式、校样、导出记录、快照 | 三版输出、校验报告、固定快照重建 |
| 教学使用 | 班级／小组／学生、练习安排、使用记录、反馈 | 已用题查询、实际使用追溯、后续选题依据 |

备份、配置、审计和迁移是各模块共用的基础能力。AI与讲义模块可以读取题目，但不得各自实现一套版本创建或审校判定规则。

### 4.2 渐进调整方式

现有 `content.py` 和 `teaching.py` 同时承担接口与较多业务逻辑，AI采纳调用了内容接口模块中的内部函数。后续新增功能时，按“先补行为验收 → 提取共用规则 → 保持原接口 → 切换调用方”的顺序调整。

优先提取质量判断和版本创建，再统一题单检查与导出条件。无需一次搬动全部文件；具体新目录随对应实施方案确定。只有出现明确的多人访问、独立扩容或部署需求后，再评估服务拆分与数据库替换。

## 5 数据模型与不可破坏的规则

### 5.1 核心关系

| 关系 | 含义与约束 |
|---|---|
| 资料 → 资料文件 → 出处 → 题目 | 一份资料有多个文件，一题可有多个出处；保留PDF页序与印刷页码的区别 |
| 题目 → 多个题目版本 → 多条解法 | 题目编号长期不变；题面、答案、小问和解析属于具体版本，方法标签属于具体解法 |
| 题目版本／解法／素材 → 审校记录 | 审校绑定被检查的对象；新版本不得仅因旧版通过就自动视为通过 |
| 题单 → 分节 → 题单条目 | 条目引用确定版本，可选解法、小问、教学角色及排版设置；同一道题的不同安排彼此独立 |
| 题单 → 导出快照 → 导出文件 | 快照保留当次内容与设置；原题后续修改不改写历史讲义 |
| 导出记录 → 使用记录 → 反馈 | 记录实际发出的版本、实际使用的题目和观察范围；计划布置不等同于已经使用 |
| AI任务 → 候选修订 → 采纳决定 → 题目版本 | 每次采纳可追溯输入、候选与目标版本，重复请求不重复入库 |

### 5.2 题目内容与管理属性

- 题面、选项、答案、小问、解法与教学说明按版本管理；已提交或已被固定使用的内容修改需遵守版本规则。
- 难度、推荐等级、预计用时是管理属性。计算难度、思维难度、综合程度分别记录；不自动合成一个总分。
- 教学用途标签表示适用建议，题单条目的角色表示这一次的实际安排。
- 标签保留知识点、教材位置、前置知识、方法、思想、用途和错误类型七个维度；详细边界见[标签规范](标签规范.md)。
- 误建重复题可以合并并保留旧编号跳转；同题多出处继续补出处；条件或问题发生数学变化的变式建立独立题目并关联。

### 5.3 版本更新与删除策略

**已有基础：** 当前版本指针、固定版本引用、导出快照、题目合并跳转和纠错记录。

**待完善设计：** 原题出现新版本时，题单显示“引用旧版／有新版”；教师查看差异后选择更新。更新必须检查所选解法、小问、素材、审校结论及逐题设置是否仍适用。失效引用逐项提示，不按位置猜测替换。批量更新先预览变化，再一次提交；遇到并发修改返回冲突并保留原题单。

正式题目优先停用或合并；已归档快照不覆盖。过程文件可按保留策略清理，但不能删除仍被出处、候选或归档引用的证据。新建清理功能前先建立引用检查与待清理清单。

## 6 功能设计大纲

### 6.1 资料接入与收题

**已有：** 临时收题、手工录题、PDF／图片上传、来源登记、证据定位、重复内容提示及TeX导入工具。

**待完善：** 统一录入入口的来源要求；批量任务同时显示成功、失败与待补充数量，失败条目可单独继续。来源未知可明确标记待确认，不能伪造出版社、年份、题号或许可结论。重复文件提示已有资料，是否合并数学题目仍须核对内容。

**验收：** 一份含模糊题、跨页题和重复题的测试材料，能分别保留证据与处理结果；修复一题不会重新处理整份材料或重复创建其他题。

### 6.2 题目编辑、解法与纠错

**已有：** 四类题型、数学预览、编辑草稿、题目版本比较、多解法、标签、题目关系和版本绑定的纠错流程。

**待完善：** 编辑前说明本次改动属于管理信息还是数学内容；修改公共题面时提示受影响的题单。修复纠错记录应关联修复版本和说明，不能只把状态改为完成。新版本审校范围按实际改动重新评估。

**验收：** 修改答案生成可比较的新版本，原讲义仍显示旧答案；纠错记录可以定位发现时的版本和修复后的版本。

### 6.3 质量状态与选用规则

这是下一阶段优先统一的业务规则。

**现状：** 已有题干、答案、解法、图形、分类、边界和方法适用范围等审校项。AI自动采纳会标明AI自复核来源并写入通过记录；通用汇总主要依据结果计算状态，尚未形成独立的人工作业确认层。题目检索与题单还分别具有可用性判断。

**目标：** 分开表示四个维度，不以一个“已完成”覆盖全部含义。

| 维度 | 含义 | 典型展示 |
|---|---|---|
| 内容整理 | 题面、答案、解析与证据是否具备 | 待补题面、待补解析、内容齐全 |
| AI处理 | 机器执行及自复核结果 | 处理中、发现疑点、自复核未发现问题 |
| 教师确认 | 人工检查的项目、版本、结论与时间 | 待教师确认、已确认、发现问题 |
| 当前用途资格 | 对本次选题、校样或正式使用的判断 | 可加入候选、可生成校样、仍需处理问题 |

**规划规则：** 未完成人工确认的题目仍可收藏、整理、加入备课候选及生成带状态提示的校样；正式教学导出默认要求题干、答案、所选解法及必要图形通过教师确认。分类、边界与方法适用范围根据课堂目标提示待查项。明确的数学错误、缺失关键条件、失效引用属于阻断问题；时间估计、难度缺项与疑似重复属于需解释的提示。此规则是目标设计，本次不改变现有导出行为。

质量判断应输出资格、阻断项、提示项和依据，检索、详情、组题及导出共同使用。评估多解题时针对本次选用的解法，不能因未选解法有疑点就失去解释，也不能因其中一解通过就把所有解法标为通过。

**实施要求：** 审校来源采用结构化信息，兼容现有记录；历史来源不明的记录保留原结论并标为待核对，不能猜测为教师确认。质量政策变更只影响后续操作，已归档文件保持原样。相关字段和兼容迁移在阶段一单独设计。

### 6.4 AI工作台

**已有：** 多协议模型接入、识题、题面区域修订、独立解题、对照参考复核、标签和难度建议、候选修订、部分采纳、预算限制与暂停恢复。

**保留的规则：** 解题阶段隔离参考答案；复核阶段再作对照。候选采纳核对证据摘要、候选修订及原题基准版本。网络中断且费用未知时保留费用预留，明确重试才重新请求；暂停在当前请求返回后生效，重启不静默恢复收费任务。

**待完善：** 工作台明确区分任务执行结果、候选质量和是否已入库。当前自动采纳默认开启，后续应显式展示本批策略：自动入库仍保留“待教师确认”，手动采纳也不能代替各项审校。默认策略如需调整，须作为独立功能变更说明，兼容已有任务。

**验收：** 重复采纳只产生一个目标版本；原题或证据变化后旧候选不能覆盖；预算不足可解释，任务中断可恢复且已完成步骤可复用。日常回归使用模拟响应，真实模型验证另行约定预算。

### 6.5 检索与选题

**已有：** 分类标签、来源、年级、题型、难度、年份等筛选，各组独立单选／多选，常用检索、连续详情浏览、选题篮及纠错入口。

**规则：** 同类多选取并集，不同类别同时满足；来源条件须由同一条出处满足，避免把不同出处的年级、年份拼成不存在的组合。质量状态、推荐等级和难度分别表达。相似度只提示候选重复，不自动合并。

**待完善：** 增加与当前教学对象、已用题记录和教师确认状态的联动筛选，显示筛选依据及空结果原因；保留检索条件和阅读位置。请求期间保留旧结果但暂停过期交互，快速操作只采用最后响应。

**验收：** 多出处、未标难度、跨组多选及快速切换结果正确；选题篮内容明确，部分加入失败可见且能重试。

### 6.6 题单与课堂编排

**已有：** 题单复制、分节、条目角色、指定版本和解法、小问选择、顺序、用时与覆盖统计、重复和未审校提示。

**待完善：** 将“课堂目标—分节任务—题目角色—时间安排”放在同一工作流程中，支持例题、跟练、变式与作业的实际安排。覆盖统计与选用解法一致；按学生作答、教师讲解、过渡预留说明用时估计。缺少估计值应显示缺项，不能当作零耗时。

新增智能组题前先完善人工组题：先确定教学对象、范围、课时和训练目标，再推荐候选与替换理由；推荐不直接改动既有题单。成套方案按教师确认后保存。

**验收：** 同题在两份题单中的角色和留白互不影响；选择部分小问时验证依赖；重复、超时、范围缺项及旧版引用均能定位到具体题目。

### 6.7 排版、导出与归档

**已有：** 自动保存与冲突检测、常用样式、纸面排序和留白、逐题换页、快速预览、实际PDF校样、三版导出及快照重建。

**规则：** 快速预览用于交互，最终分页以实际PDF为准；两者共用题目、顺序和设置来源。选项仅在四项都能放下时横排，否则四项统一竖排。学生版不得包含答案、解析或教师提示。修改内容或设置使旧校样失效，正式归档固定当时版本与素材。

**待完善：** 统一导出前的质量判断、版面检查与完成状态。明确区分生成成功、存在需复核提示和失败；失败不能显示为可用的正式讲义。保留原快照、文件摘要与编译环境信息，以便解释重建差异；跨字体或TeX版本不承诺PDF字节完全一致。

外部XeLaTeX构建必须为子进程设置可写的绝对路径 `TEMP`／`TMP`，使用同一TeX发行版的 `xelatex` 与 `xdvipdfmx`，按所需轮次先生成XDV再单独转换，核对退出码与PDF。若临时修改父进程环境须恢复原值；不修改系统环境。转换异常先检查工具、日志和权限。

**验收：** 三版内容相互对应，学生版答案隔离；复杂公式、长题、跨页与图形需检查实际PDF。原题更新后重建旧归档仍使用旧快照；校样不新增正式导出记录。

### 6.8 教学使用与反馈

**已有：** 班级、小组、学生，练习安排，实际使用记录，常见错误、实际用时、效果和下次建议，已用题查询。

**待完善：** 从导出记录直接登记使用，明确实际使用了哪些题；计划、发放、实际讲解分别记录。现有反馈主要关联一次使用记录；逐题错因与追练联动需要新增关联设计，不能把整份讲义的反馈分摊给每一道题。

追练方案应明确教学对象、原题版本、观察到的错误、所选练习与选择理由。只有实际反馈才能形成学习判断；样本不足、口径不明时保留描述，不生成可靠性不明的能力分数。

**验收：** 同一讲义只用其中三题时，已用题查询只返回实际三题；下一次选题能够区分题目身份与当时使用的版本。

## 7 状态、异常与一致性

以下为目标交互规则，各模块实施时需映射到现有状态字段，不机械新增同名枚举。

| 场景 | 系统处理 | 教师可继续的动作 |
|---|---|---|
| AI识别不完整 | 保留原页、区域与疑点，不标为内容齐全 | 修订题面区域或手工补全后处理当前题 |
| AI预算不足／费用未知 | 暂停并解释已消耗、预留及剩余额度 | 查看记录，明确继续或重试 |
| 候选已过期 | 拒绝覆盖新版本，保留候选与原输入 | 查看差异并基于新版重建任务 |
| 多页面修改同一记录 | 比较修订标识，冲突时不写入 | 保留草稿，刷新后核对再提交 |
| 批量操作部分失败 | 返回每项结果与失败原因 | 仅重试失败项，避免重复成功项 |
| 讲义编译失败 | 保留诊断与设置，不宣称正式完成 | 定位公式、素材或环境后重试 |
| 恢复备份失败 | 保留原库，隔离恢复目录 | 查看校验结果，不切换到损坏副本 |

涉及多个对象的一次业务修改在同一数据库事务内完成。网络请求、模型推理和TeX编译不长期占用写事务；先固定输入及任务标识，再执行，最后核对修订并记录结果。跨数据库与文件系统的写入不能宣称完全原子化，应设计暂存、提交登记和失败清理，确保数据库不引用未成功生成的最终文件。

## 8 数据升级、备份与运行边界

### 8.1 数据升级

现有业务库使用结构初始化与补列，结构版本为 `1`，AI结构另行初始化。后续增加审校来源等字段前，应建立有序迁移记录，包含版本、执行时间与结果；迁移前备份，用旧库副本验证，失败不推进版本号。

迁移与回退方案必须一起说明。增加字段可向后兼容时保留旧读取逻辑；不可逆变更通过恢复备份回退，不承诺自动反向转换。历史不确定数据保留并标记，不能补造确认时间或审校人。

### 8.2 备份与恢复

现有完整备份用于私有题库迁移，恢复到独立目录。后续验收覆盖数据库完整性、文件摘要、题目出处、素材、归档输出和恢复启动。密钥依赖本机账户保护时，不承诺跨机直接可用；恢复后明确提示重新配置。

开源源码包继续按公开文件白名单生成，与私有完整备份分开。源码包不包含个人题库、原卷、截图、密钥、AI任务、备份和构建产物。

### 8.3 性能与运行质量

- 检索保持分页与批量读取；后台处理有并发与预算上限，当前AI任务内最多并行处理两题。
- 性能验收使用固定机器与合成题库，逐步覆盖千题、万题规模，记录题量、素材量、响应时间分布和内存；尚无本轮实测指标，不填写保证值。
- 长操作持续显示阶段与进度；旧请求不得覆盖新结果，失败信息提供具体的继续方式。
- 服务继续限定本机使用。若未来开放局域网或多人访问，需单独设计身份、权限、并发编辑和部署安全，不能只修改监听地址。

## 9 分阶段实施顺序

下表是建议执行顺序，不是已承诺的开发日期。每阶段完成验收后再扩大范围。

| 阶段 | 优先级 | 交付内容 | 前置条件与退出标准 |
|---|---|---|---|
| 一：统一业务规则 | P0 | 审校来源设计、统一质量判断、选题／校样／正式导出规则、迁移方案、过期文档校正 | 以现有行为测试为基线；AI与人工状态清晰、旧记录可兼容、各入口同规则 |
| 二：完善备课主流程 | P1 | 新版提醒与题单更新、导出前问题清单、批量失败恢复、质量和已用题联动筛选 | 依赖阶段一；从导入到三版归档可完成全流程且无隐式覆盖 |
| 三：连接使用反馈 | P1 | 逐题反馈关联、实际使用快捷登记、错因检索与追练题单 | 先设计反馈粒度与数据结构；每条推荐可解释，使用历史可追溯 |
| 四：增强长期维护 | P2 | 引用检查与清理、合成大库性能评估、恢复演练、模块边界整理 | 核心流程稳定；优化前后数据与业务结果一致，恢复流程可重复 |

暂不进入本轮计划：在线考试、自动批改、教师共享市场、多人实时协作、自适应能力评分。出现明确需求后另立方案，避免扩大当前本地备课系统的维护范围。

## 11 设计与开发交接要求

每项功能开工前形成一份可实施说明，至少包含：

1. 教师场景、问题及成功标准。
2. 本轮范围、既有行为和目标变化。
3. 页面入口、正常流程、空状态和失败处理。
4. 数据对象、状态变化、版本与并发规则。
5. 接口输入输出、兼容与迁移影响。
6. 验收场景、测试数据、需要的实际操作检查。
7. 发布、回退、文档更新与已知限制。

整体设计负责保持术语、模块边界与业务规则一致；实现方案可在边界内调整。影响数据含义、质量资格、AI费用或历史输出的决定必须在说明中明确记录。

文档更新维护 `CHANGELOG.md`；经过相关检查与源码隐私扫描后，按项目协作规则提交、同步现有远端，更新公开清单与源码包并核对内容。网络失败应区分本地完成与远端同步状态。
