# 优化规范与验收标准

版本：1.1；更新日期：2026-10-30；适用范围：题库系统后续新功能与旧功能优化。

本文是设计与实施的共同约束，不表示所述新机制已经实现。项目提交、隐私及远端同步仍遵守[AGENTS.md](../AGENTS.md)。功能范围见[新功能设计与实施规划](新功能设计与实施规划.md)与[旧功能优化方案](旧功能优化方案.md)，架构原则见[总体大纲](系统总体设计大纲.md)。

本次新增R13—R16，依据v0.9.5复现的四项问题制定。具体证据与修复步骤见[阶段复核方案](阶段复核与优化实施方案-2026-10-30.md)，当前完成状态统一见[功能实现与验收台账](功能实现与验收台账.md)。本轮仅更新规则，不宣称问题已修复。

## 1 变更分级与完成定义

| 级别 | 典型变更 | 必需验证 |
|---|---|---|
| 文档 | 大纲、说明、规划、索引 | 现状依据、计划标识、链接与编号、隐私、公开清单与源码包 |
| 展示 | 标签、折叠、导航、按钮位置 | 原功能仍可达、键盘和窄屏、旧链接、无隐式保存或费用行为 |
| 交互与业务 | 批量加入、撤销、编辑、导出协调 | 正常与失败路径、幂等、并发、草稿、服务器规则与持久化 |
| 数据与策略 | 新字段、迁移、质量门槛、统计口径 | 旧库副本迁移、数据完整性、历史语义、回退、政策生效边界 |

完成必须同时满足：目标流程可操作、数据规则正确、关联文档一致、相关检查通过、限制如实记录、源码按规则发布。只写接口、只做页面或只通过模拟测试，均不能替代对应的端到端验收。每项完成要逐一对应原N／O验收目标；编号出现在更新记录、按钮已出现或文案已调整，不能作为完整完成的依据。

## 2 通用优化规则

### R01 一个业务事实只有一个权威来源

题目内容以具体版本为准；实际使用以使用记录及其快照范围为准；当前题单顺序以条目为准；历史讲义以固定快照为准。页面摘要、缓存和草稿都不能成为第二份独立事实。

多个入口可以保留，但应共享读取、校验与保存逻辑。禁止为统一入口复制数据库表、另存一份题目或另写一套质量判定。

### R02 优化前固定行为样本

每项任务记录旧入口、输入、保存结果和可见输出，区分本次预期改变与必须保持的部分。使用合成数据覆盖选择题、多小问、图形、多个解法、待审题及有历史归档的题目。

不能仅凭界面看起来相同宣布数据等价；保存前后核对关键字段。测试重点是业务不变量，不为单纯文案、间距或折叠结构编写镜像实现的测试。

### R03 界面按教师任务组织

常用主操作直接可见，低频管理放入明确命名的次级入口。每个页面说明当前对象及下一步，不要求教师理解数据库编号或API字段。内部编号在排查、版本和来源定位需要时可查看，不作为主要标题。

同一概念统一用词：题目、题单、分节、学生版、答案版、教师版、校样、导出记录、班级／小组／学生。确认和错误信息描述具体影响；“操作失败”后应说明可做什么。已知数学错误不能折叠到不可见位置。

### R04 保留工作上下文

进入详情、添加题目、调整排版再返回时，保留筛选、排序、滚动位置和目标对象。切换题目、数据库或班级时清除不属于新上下文的内容；明确链接优先于最近任务自动恢复。

浏览器保存的选题篮、草稿、最近记录按运行库身份隔离。旧选题篮没有可靠数据库来源时，不自动分配到当前库；提示用户核对后导入或清空，原数据在处理前保留。

### R05 保存、草稿与撤销分别表达

草稿保存到浏览器不等于提交成功；自动保存状态至少区分待保存、保存中、已保存和失败。界面提示必须对应当前输入，旧请求完成不能把后续改动标为已保存。

撤销范围明确，不承诺撤回费用、归档或跨会话业务。导出、撤销等依赖保存的操作必须等待当前保存完成；冲突时停止后续动作并保留草稿。

### R06 所有写入核对并发和重试

涉及题单的动作校验聚合修订，涉及题目内容的动作校验基准版本。服务器执行验证，前端按钮禁用只改善交互。

可重试操作使用编号绑定输入摘要；相同编号同输入返回原结果，不同输入拒绝。批量动作预先明确是整批原子还是逐项报告，不能成功一半却只返回整体失败。N01采用逐项预校验、合法项原子写入；N06采用整批预览与原子更新。

外部调用与编译不持有长期数据库写事务。文件写入使用暂存、校验和完成登记；失败后保留必要诊断并清理无引用暂存，不能让数据库引用未完成文件。

### R07 数学内容和引用必须无损

编辑器共享组件时，题型、选项键、小问键、依赖、答案、解法、素材、标签与未展示字段均有明确读写映射。公式保留可编辑源文本，不用渲染结果覆盖源文。

换题或新版更新需重新确认题目专属设置，不按解法顺序、小问序号或同名文字猜测对应。历史版本和归档不原地改写；管理属性与数学内容分开处理。

### R08 状态和费用不含混

AI完成、自复核通过、候选采纳、内容入库和教师确认分别表达；没有依据不补造审校来源。新质量门槛单独发布，不夹在界面美化中生效。

模型调用必须由明确的处理动作触发；浏览、预览表单、保存人工修订、恢复草稿、打开设置均不得附带收费请求。中断且费用未知时保留真实未知状态，不能显示成零费用。回归测试采用模拟模型，真实验证遵守当次授权预算。

### R09 布局稳定且可操作

搜索请求期间保留旧结果至新结果就绪，并禁用或隔离过期操作；只接受最后一次有效请求。结果数变化允许自然改变列表高度，不能为了固定高度截断题目。

至少检查桌面1280像素与窄屏390像素宽度；这些是验收视口，不是所有设备兼容承诺。普通页面不出现意外横向溢出，数学长式或纸面预览可在明确容器内滚动／缩放。

按钮、菜单、折叠、排序与留白调整可通过键盘完成；弹窗管理焦点，关闭后回到触发处；Escape只处理当前最上层操作。状态不能仅靠颜色区分，禁用按钮应能解释原因。保留原有数学字体及纸面比例。

### R10 输出与历史保持一致

快速预览用于编辑，PDF校样核对实际分页；正式导出固定具体修订与快照。三版共用内容与设置，学生版必须隔离答案、解析和教师提示。

有编译产物不等于验收通过，需核对所选版本是否齐全、公式、图形、缺字、越界、分页及日志。重建历史按原快照执行，模板／字体／TeX版本差异应可解释，不承诺不同环境的PDF逐字节一致。

### R11 数据升级与回退可执行

数据迁移前生成可恢复备份，在旧库副本上执行；记录迁移版本、前置条件、结果和错误。失败不推进结构版本。保留历史未知值，不推测补齐事实。

增加字段优先保持旧代码可读；停止写入或移除旧字段需单独安排。回退可以是页面回退、关闭新策略或恢复备份，但必须说明会影响哪些新数据。需要恢复时停止相关服务、恢复到独立目录、校验后再切换，禁止覆盖运行中的正式库。

### R12 文档与发布可追溯

每项变更引用N／O功能编号，更新操作说明、接口或字段字典中受影响的部分，记录已通过和未覆盖项。未开发功能保持“规划”标识，不把设计稿当作使用说明。

发布前检查暂存文件和源码隐私，白名单打包，核对清单、归档与提交内容。同步现有远端后复核提交及文件，不能把本地提交说成已经发布。私有题库、原卷、截图、密钥、AI任务和备份不进入公开仓库。

### R13 所见版本与提交目标必须一致

需要教师核对的操作必须携带本次预览过的对象、版本和必要内容摘要，不能在提交时以最新版本替换。题单修订和题目版本是两类前置条件，必须分别校验。批次预校验与写入放在同一事务；任一前置条件变化时按约定整批拒绝。

幂等重放先读取首次结果，不能因为当前状态变化而再次执行；返回的历史完成修订不代表此刻的对象修订。验收必须覆盖预览之后产生新版本、同编号内容变化和响应丢失，不只覆盖正常点击。

### R14 未确认选择不得降级为全部

明确区分全部、已选择子集与尚未重新确认。新版更新或换题时，失效的小问、解法与素材关联不能用空值偷偷扩大作用范围。首期版本更新采用先选好再提交，不把不完整状态写入正式题单。

旧空值已有“全部”含义时继续兼容，不能统一改成错误；新增请求用显式模式表达意图。需要保存未完成草稿时另行设计独立状态与输出限制。相同小问键不等于数学含义不变，选定内容及依赖须重新核对。

### R15 撤销按业务效果恢复

一次操作的完整效果包含条目、局部排版覆盖、顺序和必要的引用，不能只恢复一行数据。逆操作记录格式版本和前后条件，恢复范围只覆盖该操作影响的对象，不回写无关的整份布局。

分组撤销应整体成功或整体不变；新动作、重做分支、跨页修改、延迟自动保存和旧格式逆操作都有明确处理。缺少完整历史快照时禁止宣称恢复原样，也不猜测缺失设置。

### R16 可编辑字段必须纳入并发契约

每个可编辑字段必须映射到修订摘要或说明独立校验方式；业务内容不得因维护漏项而不参与冲突判断。预计作答／讲解时间、教学覆盖、前置要求、模板和备注均需核对，不能只检查题目编号与版面字段。

摘要格式改变时使用新前缀，旧页面明确刷新后核对，不静默转换成当前值放行。测试按字段矩阵逐项改变并检查修订；时间戳、等价JSON键序等排除项另作验证。新增字段的设计、实现和验收同时更新该矩阵。

## 3 通用状态矩阵

每个可交互功能至少明确以下六类状态，不要求所有状态都用弹窗。

| 状态 | 必须表现 | 禁止表现 |
|---|---|---|
| 空数据 | 说明当前没有什么，提供合理下一步 | 伪造样例业务数据混入正式库 |
| 正在执行 | 标明动作，防重复，长任务有阶段反馈 | 无反馈地重复触发或把旧结果当新结果 |
| 成功 | 展示对应对象及完成结果 | 请求发出就显示成功 |
| 部分成功 | 逐项结果、失败原因及重试范围 | 自动重新执行全部已成功项 |
| 失败 | 保留输入，区分网络、内容、环境等原因 | 清空表单或暗中换用默认参数 |
| 冲突／过期 | 保留草稿，定位变化，重新核对 | 静默覆盖或自动把旧设置套到新内容 |

## 4 验收数据与场景库

使用独立数据库构造以下数据，不复制真实学生信息或私有试卷：

- 四种题型，包含复杂公式、长题、跨页图形、多个解法、带依赖的小问。
- 同题多出处、重复题与变式、已合并题目、缺少难度或用时的题目。
- 人工确认、仅AI自复核、历史来源未知、明确错误、不同审校来源有冲突的版本。
- 一题多个版本，两份题单引用不同版本，一份已经正式归档并记录部分使用。
- 两个独立教学对象、计划与实际不一致的使用、整次反馈与逐题反馈。
- 一份旧结构测试库、一份恢复副本、两个浏览器页面及模拟延迟／断网响应。

上述是目标验收数据目录，不表示演示库已含全部样本。每次仅准备与本项变更有关的数据，并标注样本版本。

## 6 外部TeX验收规范

所有外部XeLaTeX构建先在可写工作目录建立临时目录，将其绝对路径作为子进程 `TEMP` 与 `TMP`。优先复制父进程环境到子进程环境；如修改了父进程变量，结束时恢复原值，不更改机器全局环境。

解析并记录同一发行版的 `xelatex` 与 `xdvipdfmx` 路径；按项目所需轮次用 `xelatex -no-pdf` 生成XDV，再用匹配转换器生成PDF。核对每步退出码、日志与最终PDF。转换器异常先检查实际工具和目录权限，不能仅凭异常码归咎于题目源文。

用实际PDF检查封面、题号、四选项排列、长题分页、图形、作答留白及三版对应关系。保留必要的测试产物和问题页证据，测试构建目录与源代码及正式讲义目录分离。

## 7 体验评价方式

对同一合成任务比较优化前后操作，不用主观“更清爽”代替证据。

| 目标 | 记录方法 | 判定方式 |
|---|---|---|
| 减少重复输入 | 记录同一信息被要求手工输入的次数 | 同一任务内已知题单、讲义、对象信息可带入并可核对 |
| 减少任务中断 | 记录跨页、重新筛选、重新定位次数 | N01连续选题不需反复返回题单；详情返回保持位置 |
| 降低返工 | 记录误删、错排、错样式后的恢复动作 | N02范围内可撤销，未支持操作明确说明 |
| 提高状态可信度 | 对照页面提示、数据库和最终文件 | 已保存、已入库、已确认、已使用分别有对应证据 |
| 保持响应稳定 | 在固定数据、机器、视口和模拟延迟下观察 | 无过期覆盖、闪空或意外跳位；真实数量变化允许重排 |
| 保持性能可评估 | 记录题量、素材量、请求耗时分布与内存 | 先测现状，再定目标；未实测不写保证值 |

不默认启用外发遥测。需要了解低频功能价值时，先使用本地可查看的操作记录或由教师反馈；不得为评估体验上传私人题目和学生数据。

## 8 发布前检查与回退演练

1. **范围核对：** 本次N／O编号、变更文件、预期行为和明确不变部分均有记录；无混入无关修改。
2. **数据核对：** 测试库隔离；迁移或重大规则变更前有可恢复备份；旧快照与历史记录保持。
3. **功能核对：** 本项验收编号逐条有结论；失败和冲突分支验证，限制未隐藏。
4. **界面核对：** 默认、空、错误、窄屏、键盘、返回与草稿路径符合相关规则。
5. **输出核对：** 涉及排版时核对实际PDF及三版隔离；纯文档更新不要求编译。
6. **回退核对：** 明确代码回退是否足够，新增字段与新数据如何保留；需要恢复时在副本演练。
7. **发布核对：** CHANGELOG、说明、清单、源码包与提交一致；远端同步结果有证据。

首期新入口可以保留旧路径作兼容，但不得长期维护两套不同规则。确认无调用方后再删除适配代码；删除也是可独立核验的变更。

## 9 功能交接与验收记录模板

以下字段用于每个实际开发任务的说明，不需要为本轮规划预填通过结果。

| 字段 | 必填内容 |
|---|---|
| 任务与基线 | N／O编号、实现提交、应用版本、数据结构版本 |
| 用户问题 | 具体操作场景与原先障碍 |
| 变更范围 | 新旧入口、行为差异、保留能力 |
| 数据与接口 | 输入输出、状态、引用、幂等、并发、迁移 |
| 验收编号 | 本项A／B／C等用例及必要关联用例 |
| 验收环境 | 合成数据版本、浏览器视口、依赖环境；公开文档不含私人路径 |
| 验收结果 | 通过／失败／跳过／未验证，附原因与证据位置 |
| 兼容与回退 | 旧数据、旧链接、旧客户端、回退步骤及数据影响 |
| 发布结果 | 本地提交、远端核对、源码包摘要、未完成事项 |

功能完成后更新关联设计的实现状态和提交索引，保留当时设计基线；不得因规划已合并到仓库就把对应功能标为已上线。
