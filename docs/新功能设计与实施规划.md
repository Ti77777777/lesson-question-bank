# 新功能设计与实施规划

版本：1.0；日期：2026-10-29；实现基线：应用 v0.4.4。

状态：设计方案，本文所有新增行为均待开发。本轮不改变程序、数据库或收费调用行为。整体边界见[系统总体设计大纲](系统总体设计大纲.md)，旧入口调整见[旧功能优化方案](旧功能优化方案.md)，共同约束见[优化规范与验收标准](优化规范与验收标准.md)。

## 1 目标与范围

以“给一节课制作并使用一份讲义”为验收主线：进入上次题单，连续找题，调整内容和版面，导出，登记使用，再依据实际问题改进下一次选题。

优先减少重复填写、离开当前任务和误操作后的返工。新增功能不得以新增首页、增加必填字段或自动收费替代明确的操作设计。

## 2 N01 为当前题单连续选题

**场景与入口。** 教师在“题单 → 添加题目”进入完整检索页，页面顶部显示“正在为《题单名称》选题”、目标分节和“返回题单”。直接打开检索时可选“加入已有题单”或继续使用选题篮新建题单。

**主流程。** 选择目标题单及分节 → 保持检索条件浏览 → 单题加入或勾选后批量加入 → 原位显示已加入状态、题量和用时估计 → 返回题单。点击题单名称可更换目标；更换目标不清空筛选条件。当前题单中已有的题目显示“已在题单”，再次添加须明确选择“再次加入”，不把重试当成再次加入。

**数据与边界。** 目标题单是当前标签页上下文，路由可携带题单／分节编号但服务端必须重新验证归属；浏览器存储按数据库身份隔离。条目保存提交时选定的题目版本；若浏览期间原题更新，返回版本变化信息，由教师重选，不静默换用新版。目标题单显示的用时缺项单独计数，不能记作零分钟。

**接口草案。** 新增 `POST /api/collections/{cid}/items/batch`，输入操作编号、题单基准修订、分节和题目版本列表。先校验每项，将合法项在一个事务中加入，返回逐项成功、重复、版本变化或无效原因及新修订；写入异常则整笔回滚。基准修订冲突则整批不执行。重复同一操作编号返回原结果；改动输入须用新编号，仅重试失败项。

**失败处理。** 题单失效、分节删除、跨库上下文失效时保留当前选择，要求重新指定目标；不能自动改投另一题单。响应丢失可按原操作编号重取结果。

部分成功后重试失败项，使用新操作编号及响应中的新题单修订；如期间另有修改，先重新获取并核对，不以第一次请求的旧修订继续写入。

**验收。** N01-A：同一页面向指定分节加入多题，检索位置不丢；N01-B：双击或超时重试不重复加入；N01-C：部分无效项有逐项结果，题单并发冲突无部分写入；N01-D：切换数据库不会沿用另一库的题单与选题篮。

## 3 N02 撤销与重做

**范围。** 首期支持题单条目的加入、移除、排序，留白、换页及样式套用；一次拖动算一次操作，一次批量加入算一次操作。首期不撤销题目合并、教师审校、正式归档、使用记录或已发出的AI请求。删除整个分节等未纳入操作不显示可撤销承诺。

**交互。** 题单及排版页提供“撤销／重做”，附当前动作描述，例如“撤销：移除第3题”。快捷键只在非文本编辑区域作用于题单；输入框中的撤销仍由编辑器处理。自动保存继续保留，撤销是一次新的保存，不删除审计历史。首期在当前页面会话保留最近20步；刷新后不承诺恢复操作栈，页面说明其范围。

**数据设计。** 规划题单操作记录，保存操作编号、类型、前后修订、受影响对象的前后值、结果与时间。撤销栈在当前页面会话中，服务端操作记录支持幂等及核对；其保留期初始设为30天，清理前不得仍属于有效操作请求。恢复被移除条目时保留原条目编号和完整设置，序号不得分配给其他对象。历史归档不受影响。

**接口草案。** N01批量操作及题单编辑逐步统一接入可逆命令服务；规划 `POST /api/collections/{cid}/commands`，动作包括编辑、撤销、重做，携带基准修订与操作编号。撤销仅允许当前页面栈顶操作，且当前题单修订与预期相同；另一个页面有任何题单修改时停止撤销，不回写旧的整份快照。新动作会清空重做分支。

**保存竞态。** 执行撤销前结束当前拖动、提交并等待排队保存；不能让延迟到达的旧保存覆盖撤销结果。失败时保留页面操作栈但标记待核对，刷新后从服务端当前状态重新开始。记录30天保留期不是跨会话撤销承诺。

每次撤销／重做使用新的请求操作编号，并引用被恢复的原动作编号；网络重试才复用该次请求编号。成功后以服务端返回的新修订更新操作栈的下一步预期，核对受影响字段仍符合所需前态／后态，不能沿用原动作的旧修订阻断所有连续撤销，也不能绕过并发验证。

**验收。** N02-A：移除、恢复后题目身份与设置完整；N02-B：连续输入合并成合理动作，拖动不产生几十步；N02-C：慢保存、双击撤销及跨页并发不覆盖他人修改；N02-D：文本框原生撤销、20步边界与重做分支符合说明。

## 4 N03 统一数学编辑器

**现状。** 手工新建、题目新版本与AI候选修订分别提供表单；选项和复杂内容的编辑方式并不完全一致。目标是共用输入与预览组件，同时保留各入口不同的提交语义。

**首期能力。** 题干、动态选项、正确选项、小问、简明答案、解法和教学提示分区编辑；常用分式、根式、上下标、不等号、集合和矩阵通过按钮插入LaTeX片段。保留直接输入LaTeX，预览只负责显示，不在保存时把公式转成图片。

**主流程。** 从任意编辑入口打开一致表单 → 实时查看预览 → 校验题型、选项、小问和依赖 → 查看本次保存范围 → 提交。新建生成题目；旧题修改生成新版本；AI题面修订使相关解答需要重新处理，AI答案修订保存为候选修订。只有明确继续AI处理才产生相应请求。

**数据保护。** 共用编辑模型需保留未显示的素材引用、出处、教学字段、解法标签和小问稳定键；未编辑的字段不以空值覆盖。小问删除需提示依赖它的小问。新版本下解法编号可变化，但不得按数组位置猜测旧解法对应关系。草稿按数据库、编辑对象、编辑模式及基准修订隔离，旧草稿恢复前核对版本。

**异常。** 公式预览失败允许继续保留草稿并定位表达式；业务结构无效时阻止正式提交并保留原文。浏览器存储不可用时明确告知草稿未保存。选择题改变题型后，隐藏字段不得默默删除；提交前提示具体变化。

**接口策略。** 首期复用现有创建版本、创建题目和AI修订接口，不建立一个抹平语义的通用保存接口；服务器统一内容校验，前端只共享组件。字段兼容矩阵随实现附在[API说明](API.md)。

**验收。** N03-A：同一复杂题在三个入口显示及保存一致；N03-B：公式、素材、小问、解法标签无损往返；N03-C：过期草稿与并发版本不覆盖新内容；N03-D：保存AI表单本身不发起收费处理。

## 5 N04 按教学对象提示已用题

**入口。** 检索和题单顶部可选班级、小组或学生，并选择观察区间，默认近30天、可改。题卡显示“该对象最近使用日期”，提供“仅未用过”筛选；复习课可保留已用题，不一律禁选。

**计算口径。** 已用指实际使用记录内的题目，计划使用、仅导出均不算。只登记部分题目时只统计该部分。默认按题目身份提醒，同时可查看使用时的版本；修正答案后的同题仍属于用过。没有记录显示“未记录使用”，不能断言学生从未见过。合并题目时沿保留身份及旧编号映射查询，避免丢失历史。

**已有基础。** 后端检索已支持 `exclude_audience` 与 `exclude_days`；需要补前端联动及批量取使用摘要，不能逐题请求造成列表变慢。对象及时间范围写入检索状态与常用方案；复用方案时验证对象仍存在。

**不扩张范围。** 当前对象不是班级花名册，没有成员关系时不能推断“班级用过＝某学生用过”，也不能自动合并同名对象。未来有成员模型后另行确定继承规则。

**验收。** N04-A：同一讲义只实际用三题，另几题不被排除；N04-B：班级和学生记录互不串用；N04-C：边界日期、版本更新、题目合并与无记录提示正确；N04-D：复习模式可以保留已用题并解释日期。

## 6 N05 从讲义快捷登记使用

**入口。** 正式导出成功页、归档详情和题单的导出记录提供“登记使用”；已有练习安排提供“按此安排登记使用”。系统带入导出记录和题目列表，教师填写对象、实际日期、用途，可选择全部或部分题目。

**确认边界。** 导出不自动登记使用，下载也不代表已发放；标记已发放不自动视为已讲解。计划日期可以作为参考展示，实际日期必须由教师确认；默认今天时也在提交前明确显示。失败的导出记录不能登记实际使用。

**数据与接口。** 继续使用 `assignment`、`usage_log`、`feedback`，不再建一份“课堂记录”重复保存。扩展使用创建接口的幂等操作编号；相同讲义同日允许不同对象或不同用途的真实多次使用，不能用日期组合硬性去重。若关联安排，核对对象、导出记录及实际题目，变化需要解释但允许合理偏离计划。

**提交后。** 显示已登记的对象、日期和题目范围，提供“补充反馈”，反馈可跳过。再次登记沿用上次对象只能作为可见默认值，不能后台自动提交。修改使用记录按现有审计要求保留变化依据。

**验收。** N05-A：从讲义进入不必重新选择该讲义；N05-B：重复点击只有一条记录，但主动登记第二次可成立；N05-C：部分题使用、安排变更与实际日期可追溯；N05-D：仅导出后已用题查询不变化。

## 7 N06 原题新版提醒与显式更新

**入口。** 题单标出“有新版”，点击查看旧版与新版题面、答案、解法、图形及审校差异；题目修订完成后可查看受影响的可编辑题单。归档只显示历史所用版本，不提供原地升级。

**更新流程。** 勾选待更新条目 → 预览每条差异和失效设置 → 为新版重新选择解法／小问 → 明确保留或重设留白等安排 → 原子提交。教师也可继续使用旧版，提示保持可见且不擅自替换。批量预览返回短期变更凭据，绑定题单修订、旧引用和目标新版本；提交时再次验证。

**保留规则。** 条目编号、分节、教学角色、位置与本班备注默认保留。旧解法／小问编号不可直接套到新版；只有经过校验的稳定对应才可预填，否则必须选择。旧审校结论不直接复制；新版质量按统一规则重新计算。图形变化、题干变长可提示重新检查留白和分页。

**接口草案。** 新增 `POST /api/collections/{cid}/version-updates/preview` 和 `/apply`；预览不改数据，提交校验基准修订、目标版本、选择范围及凭据摘要。整批原子执行，任一版本再次变化或失效均拒绝该批，保留原题单供重新预览。历史讲义及其使用记录不变化。

**验收。** N06-A：新题出现后旧题单只提示、不自动变更；N06-B：旧解法、小问失效时不误配；N06-C：预览后并发变更阻止提交；N06-D：更新题单后重导旧归档仍使用原快照。

## 8 N07 在题单中换一道题

**入口。** 题单条目提供“换一道”，打开保持题单上下文的候选侧栏；默认使用当前主考点、题型和已知思维难度范围，可调整条件。

**选择依据。** 候选显示命中的考点、难度差异、所需前置知识、所选对象已用情况和质量状态；信息缺失就明确显示，不编造“等价替换”。首期按现有标签与筛选实现，不调用模型。若没有候选，展示条件并由教师选择放宽，不能后台自动扩大范围。

**替换范围。** 原条目编号、分节、顺序与教学角色保留；新题使用自己的题型、答案、解法及审校状态。旧题的小问选择、指定解法、提示级别和题目特定留白先列出待重设项；不能把题目专属配置机械复制。教师核对后一次提交，旧题本身不删除。已归档内容不变。

**技术依赖。** 复用N01上下文、N04已用信息、N06引用校验及N02操作服务。新增替换动作携带旧条目引用和新版本，提交时检查两者；撤销恢复完整旧条目并恢复其配置。

**验收。** N07-A：替换只改变选定条目；N07-B：无合适题时不擅自放宽；N07-C：解法和小问不串题；N07-D：并发失败不留下半个替换，成功后可撤销。

## 9 N08 继续上次工作

**交互。** 仅默认启动入口显示“继续上次工作”和最近三份题单；已明确打开AI任务、题目或题单链接时遵循该链接，不被自动跳转。没有历史时保留清晰的新建／导入入口，不建空白统计看板。

**存储。** 最近访问保存在当前浏览器，并按数据库身份隔离；保存题单编号和编辑模式，不复制题目内容。恢复前向服务端核对对象存在与访问状态；数据库改变、题单失效或存储禁用时安全退回题单列表。草稿恢复仍沿用专门流程，最近任务不代替草稿。

**验收。** N08-A：从默认入口可直接回到最近题单；N08-B：显式AI链接不被抢占；N08-C：另一数据库、无痕浏览或失效记录不出现错题单；N08-D：删除最近访问记录不删除业务数据。

## 10 N09 逐题反馈与追练

**交付条件。** 先完成N04、N05并具备可核验的真实使用范围，再实施逐题反馈。现有整次使用反馈继续保留，不能自动复制到每一道题。

**数据草案。** 新增使用条目反馈关联，绑定使用记录、归档条目、题目版本；保存具体错误现象、观察说明、样本口径及下一次建议。没有逐题观察时只填整份讲义反馈。记录错误类型可关联现有标签，但不自动修改公共题目的预计易错点。

**流程。** 打开一次使用记录 → 在实际使用的题目中选题记录问题 → 点击“找练习”进入相应考点／错因筛选 → 教师挑选候选并建立追练题单。保存追练来源，以便解释为什么选这些题；不根据一条反馈生成学生能力分数。

**验收。** N09-A：未使用的条目不能被登记为本次实际观察；N09-B：同一题不同班级反馈互不覆盖；N09-C：生成追练不改变原讲义和原反馈；N09-D：样本不明时不展示统计性结论。

| 共用项 | 设计要求 | 使用功能 |

| 数据库身份 | 现有草稿以数据库路径和建库信息区分；规划统一运行库身份供上下文、选题篮、最近记录使用。恢复副本应有独立运行身份，保留来源身份用于追溯 | N01、N03、N08 |
| 题单修订 | 以题单信息、分节、条目及排版的聚合修订校验写入；现有排版已有摘要修订，可提取共用。题目最新版本变化另外核对 | N01、N02、N06、N07 |
| 操作记录 | 同一操作编号与相同输入返回原结果；同编号不同输入拒绝；同时持久化结果和业务修改 | N01、N02、N05、N06、N07 |
| 版本映射 | 显式核对新旧解法、小问和素材的对应，不按顺序或名字猜测 | N03、N06、N07 |
| 质量判定 | 复用O09统一规则；既有“通过”不自动解释成人工确认 | N01、N03、N06、N07 |
| 逐题反馈 | 与使用快照绑定的新增关联，保留整次反馈；支持独立迁移与回退 | N09 |

操作编号记录过期后不能盲目重放旧请求；返回已过保留期，核对当前业务状态后创建新操作。正常操作不把原题内容、浏览器草稿或密钥写进可公开日志。

## 12 分批实施与开发任务

本节是新功能与旧功能的统一发布顺序。[旧功能优化方案](旧功能优化方案.md)中的O编号共用以下批次。

| 批次 | 范围与开发任务 | 依赖与退出标准 |
|---|---|---|
| M0 规则与基线 | 固定现有行为样本；定义运行库身份、聚合修订、操作记录和迁移；完成O09来源／资格规则的详细契约；核对旧入口和保存字段 | 无前置；新旧字段映射、冲突规则、回退方案和验收样本可执行。低风险页面整理不必等待全部新数据能力开发 |
| M1 选题与输出 | N01连续选题、N02首期撤销、N08继续工作；O01统一导出、O02排版职责、O05详情层级、O06版本入口 | 写操作先具备M0对应基础；连续选题到导出可完成，撤销并发正确，原模板与三版内容保持 |
| M2 编辑与使用 | N03编辑器、N04已用提示、N05快捷登记；O03统一录入入口、O04使用表单联动、O07筛选整理、O08系统设置、O10编辑组件统一 | M1稳定；复杂题无损编辑，使用统计口径明确，旧链接与现有记录兼容 |
| M3 版本与质量 | N06新版提醒、N07换题；O09结构化审校来源、统一质量计算及正式导出策略切换 | 迁移测试与来源映射通过；提示层先发布，新门槛单独启用并说明影响；历史讲义保持 |
| M4 反馈与长期维护 | N09逐题反馈、手动追练；合成大库评估、备份恢复演练、低频功能使用观察 | 已有可靠使用记录；追练理由可追溯，恢复验证通过；是否继续智能推荐另行评估 |

### 每项任务的开发拆分

1. 将本项验收编号转为用例及数据样本，记录现状。
2. 明确复用与新增的数据／接口，完成迁移和回退验证。
3. 实现服务端规则与异常路径，再接页面操作及草稿。
4. 覆盖正常、无数据、部分失败、超时重试、并发、旧数据六类场景。
5. 完成真实页面检查；涉及输出时检查实际PDF；更新说明与源码包。

### 暂缓项

全自动智能组卷、AI自动生成变式、学生画像与能力分数、多教师协作、在线答题暂缓。先保证教师可解释地选题、换题和记录使用。没有使用数据时不据推测删除低频能力；没有固定环境实测时不承诺性能数值。

## 13 跨功能验收任务

以独立测试库中的虚构班级及合成题目执行：

1. 从上次题单进入检索，向两个分节连续加入题目，期间重复提交和切换筛选。
2. 移除、撤销、排序、套用样式并重做；模拟另一个页面修改，确认停止过期覆盖。
3. 编辑一题的复杂公式及小问，检查新版提示；显式更新一份题单，另一份继续保留旧版。
4. 换一道题，核对所选解法和小问，检查三版校样并正式导出。
5. 登记只使用其中三题；再次为该班选题，确认仅这三题计入已用。
6. 给其中一题记录具体错误，建立追练题单；核对原讲义、旧版本和历史记录未变。

开发前不得把上述任务标成已通过。验收证据包含应用提交、测试数据版本、实际步骤、结果与未覆盖项，格式按[优化规范与验收标准](优化规范与验收标准.md)执行。
